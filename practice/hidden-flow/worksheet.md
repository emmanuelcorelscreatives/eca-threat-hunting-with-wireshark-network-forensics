# Worksheet

Keep every answer labelled OBSERVED FIXTURE, DESIGN CONTEXT, INFERENCE or UNKNOWN. This exercise is separate from the unavailable lecture case.

1. Read the original design CSVs and README. Identify the intended asset alias, two peers, authored time window and hypothetical inventory label. State what would be needed to establish a real capture point, directional coverage, host mapping and clock reliability in an authorized case.
2. Apply the asset filter and inspect both directions. Use TCP Conversations to record each four-tuple, stream ID, first/last UTC timestamps, duration, packet count, byte count and directional totals. Distinguish Ethernet packet bytes from complete PCAPNG filesystem size. Confirm which peer has a single long connection and which has three new connections. Identify SYN/SYN-ACK/ACK and closure packets. Do not copy a design row as packet evidence.
3. Compare peer graphs with identical packet-selection rules and 1-second versus 180-second bins. Record actual interval and axis. Use supplied CLI graphs if needed. Follow at least one peak into its packets: which stream and handshake support a distinct new session? Which later packets are only closing an existing stream? Explain why a long flow is not continuous activity and why bytes cannot count protected application requests.
4. Inspect both hello messages in one candidate stream. Record exact frame numbers and supported-version field. Run the name-visibility filter. What can the empty result establish about this file? Give four alternatives for missing readable DNS in a real case (cached answer, missed exchange, direct IP, encrypted DNS). Do not assert this fixture demonstrates any one of them.
5. Explain why a visible outer server name would not necessarily identify an ECH-protected backend and why an offer cannot prove acceptance. Explain the distinction between visibility of QUIC Initial packets and later protected requests. These are conceptual questions: the supplied fixture contains neither ECH nor QUIC.
6. Provide a harmless alternative for three short periodic connections and an appropriate baseline or operational context to seek. Explain why the peer address, flow size and hypothetical inventory label cannot identify a hidden website, initiating process, approved update, malicious intent or protected content.
7. Write a claim ledger: hypothesis; exact scope; filter/pivot; packet references; observation; alternative; confidence in that specific claim; missing field; next authorized action. Draft a UTC-scoped endpoint request for process/connection linkage and any retained name fields. Draft a proxy alternative conditional on confirmed traversal and ask what it actually saw, logged and did not retain.
8. Homework: repeat the method on a capture you are independently authorized to use. Document collection point, time basis and asset mapping first. Pick one peer, compare connections and timing, inspect supporting packets and supply a harmless alternative. If coverage is insufficient, record that limit. This kit enables that work; it does not claim a learner has completed it. Finish with Stage 15's question: what channel and observable claim does your evidence support?
