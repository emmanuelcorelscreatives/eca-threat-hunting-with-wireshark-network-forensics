# Schema and evidence boundaries

`fixture_spec.json` is generator input. `synthetic` labels its design; `epoch` is UTC Unix seconds for the first packet. `asset` and every `peer` use documentation-range IPv4 addresses. Each `connections` item has a design `id`, client/server ports, relative `start` seconds, relative-to-start exchange/probe offsets in seconds, `duration` until the first FIN, and raw client/server initial sequence numbers. `duration` differs from the observed first-to-last packet span because close acknowledgments follow at +0.01/+0.02 seconds. Each payload exchange has a literal request and response plus an ACK; no TLS or real application protocol is implemented. Probe labels are validated by TShark rather than assumed from design.

The PCAP contains Ethernet/IPv4/TCP bytes with microsecond timestamps and generated checksums. MAC addresses are lab placeholders. No external packets or production data were collected. `fixture_manifest.json` records exact capture SHA-256, frame total, simulated viewpoint, time convention and coverage/payload limits. It is separate from the current file inventory.

`asset_inventory.csv` columns describe fictional asset ID, IP mapping, role, team and synthetic status. `approved_configuration.csv` describes ID, asset, fictional software, peer, port, UTC start/end bounds, owner, enrollment and synthetic status. The configuration window is an administrative claim; neither a packet nor process identity. `simulated_owner_record.md` scopes it further. All times use UTC with `Z`; packet epochs retain subsecond precision.

`decoded-fields.csv` is actual TShark field output: original frame, epoch and relative seconds, source/destination IP and TCP ports, assigned stream, flags, raw sequence/ack values and TCP payload length. TCP stream indices are dissection assignments for this full capture, not portable incident IDs. `verification.json` contains actual checks and observed keepalive frame lists. `execution.json` records commands, exit codes, rebuild hashes and negative checks. Screenshot receipts bind exact source capture hashes and actual native platform. File length, packet bytes and directional conversation byte totals are distinct measurements.

In the worksheet, packet observations need original frame references and stated scope. Administrative explanations cite their supplied record. Inferences and missing evidence remain separate. Capture bounds do not prove continuous collection or behavior outside the file. Process identity remains unknown without separate suitable evidence.
