# Data dictionary, provenance, and evidence limits

This directory contains synthetic Academy coursework and a separate actual controlled loopback experiment, not the narrated incident. The immutable `case-context.csv`, `executed-fixture-spec.json`, `offline-builder.py`, `practice.pcap`, and named execution logs are distinct kinds of evidence. This dictionary describes them; it does not change their contents. Versioned repository publication has not occurred.

| Resource | Meaning and limits |
| --- | --- |
| `case-context.csv` | UTF-8 scenario metadata, **not** a packet export. `field` is a context key, `value` its stated value, and `basis` its origin or unresolved status. It has 16 data rows. Fictional mappings, the asset-side point, proposed interruption, asset time zone, proposed shift, and unknown approval must not be promoted to measured coverage or owner evidence. |
| `executed-fixture-spec.json` | Actual deterministic builder input: `version: 1`, `synthetic: true`, and 34 ordered, explicitly UTC-timestamped `events`. Each event specifies `kind`, `src`, and `dst`; its TCP events include `sport`, `dport`, `flags`, `seq`, and `ack`, with text on selected payload-bearing events; its two UDP events contain text span markers. Authored sequence numbers and intended text are design inputs, cross-checked where stated against decoded fields—not proof that an endpoint sent live traffic. |
| `offline-builder.py` | Packaged offline packet author. It accepts `--spec` and `--output`, writes a PCAP, and **overwrites** that output. It supports additional event kinds, but support in code does not mean they occur in this input. Build only into a fresh output path if preserving originals. |
| `practice.pcap` | Packaged 2,585-byte Ethernet PCAP with SHA-256 `bf5c781e12dc5fb86b65b724464bb70e944b1eb483910fd00facad9d2004f0bd`, reported in `capture-info.stdout.txt`. A deterministic rebuild using the executed spec and packaged builder was reported identical. Its packet observations are confined to this synthetic fixture. |
| `*.stdout.txt` and `*.stderr.txt` | Saved results of executed, read-only, pinned TShark 4.4.0 Linux/`capinfos` calls. Named stdout files are the citations for decoded values; the TShark stderr files' root-user warning is not a packet finding. These logs are CLI-only. Native Linux GUI evidence is mapped separately; Windows behavior was not executed. |

`capture-info.stdout.txt` records PCAP storage size, captured data size, frame count, and timestamp bounds. `all-frames.stdout.txt` has a **tab-separated header** naming decoded fields. `frame.number` is the capture frame reference; `frame.len` and `frame.cap_len` are per-frame lengths, whereas `tcp.len` is TCP payload length. `tcp.payload` and `http.file_data` are **hexadecimal byte strings**: `78` in `http.file_data` is one byte, `x`. `tcp.seq_raw`/`tcp.ack_raw` are raw on-wire values; a Wireshark display with relative TCP sequence numbering enabled may show different values. `tcp.stream` is a decoder-assigned stream index, not an event ID, port, or file reference. `frame.time_utc` is a human-readable UTC date/time; `frame.time_epoch` is decimal Unix-epoch seconds. The PCAP has microsecond timestamp precision (`capture-info.stdout.txt`), even though TShark formats these fields with nine fractional digits. The pinned 4.4 inventory does **not** support `frame.time_iso8601`; no old extraction using that field is a verified result.

`tcp-conversations.stdout.txt` separates TCP endpoint/port pairs and reports relative start and duration plus directional **frame** counts/bytes. `ip-conversations.stdout.txt` aggregates by IP pair; its long asset/peer duration is not a continuous TCP session. `outbound-frames.stdout.txt` contains the exact asset-to-peer IP filter's frame numbers, UTC times, stream IDs, and frame lengths. `outbound-io-60-10.stdout.txt` reports 60- and 10-second **capture-relative** matching-frame bins, including many zero bins; these are not GUI graph observations or unique content sizes. `protocol-hierarchy.stdout.txt` reports decoded protocol categories. Empty `malformed.stdout.txt` means no frame matched that executed filter, not that every conceivable validation or collection condition was proved sound.

All actual event IPs are documentation IPv4 addresses. Frames **1** and **34** are UDP text markers to `192.0.2.53` on non-DNS ports; the actual spec includes **no DNS query or answer**. `files.academy.test` appears as the literal internal HTTP Host header in frame **5**, not as an observed DNS answer. `collector.partner.test` is only the CSV peer label, with no observed resolution. Frames **5–6** contain authored HTTP request/response text, not evidence of a running service, local file creation, collection, storage, or permission. Peer frames contain small plaintext TCP data and replies; there is **no TLS flow or encrypted application-data demonstration**. No host identity, file/process, proxy, storage, ownership, or approved-schedule records are included.

The CSV's `first_event_design_utc` and `last_event_design_utc` bases still literally say “unverified fixture design” because the CSV is preserved unchanged. Their **timestamp values** now agree with decoded UTC frames **1** and **34** in `all-frames.stdout.txt` and the bounds in `capture-info.stdout.txt`; that does not verify coverage between them. Likewise, the fictional `2025-02-05 22:00–22:15 UTC` collector gap is context only: an absence of packets cannot validate an interruption. The shift and asset time zone are proposed context, not an actual owner's schedule; `analyst_time_zone_example` is not the student's workstation setting. Authorization, internal-file staging, a link between internal HTTP and peer data, encrypted-file identity, and sensitive-data loss remain unresolved. A richer source-lesson exercise needing any of those observations requires additional authorized, checked evidence; the short plaintext TCP exchanges cannot substitute for it.


## Additional actual collection

actual-tls-staging.pcap is a real loopback-only TLS collection, paired with actual-host-file-events.json. Host log times are Unix nanoseconds; packet field times are Unix seconds. Slice boundaries use half-open byte offsets. File sizes and receive sizes come from host instrumentation; encrypted TLS record lengths include protocol overhead. The original fixture restrictions above refer to practice.pcap only. Client/server directions in the actual loopback collection require port pairs because both addresses are127.0.0.1. native-validation.md and native capture receipts bind actual PNG bytes and source PCAP hashes. current-kit-inventory.json is the current delivered member inventory; old assembly/execution manifests are historical.
