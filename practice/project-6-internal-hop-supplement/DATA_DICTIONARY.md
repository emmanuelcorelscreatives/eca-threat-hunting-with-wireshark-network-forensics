# Data dictionary — authored synthetic CSVs

All rows are **scenario records**, not packet-derived observations or real Windows exports. Times are ISO-8601 UTC with `Z`; intervals use inclusive start and **exclusive end**. Empty CSV fields mean not supplied, not an observed absence. IDs are local to this exercise.

- `sensor-coverage.csv`: `sensor_id` (OP-A/OP-B); `observation_point` (planned placement); `planned_start_utc`, `planned_end_utc_exclusive` (planned comparable-time coverage, **not PCAP packet bounds**); `raw_clock_offset_seconds` (raw capture timestamp minus comparable UTC); `offset_uncertainty_seconds` (authored scenario uncertainty); `planned_directions` (paths intended to be visible both ways); `paths_outside_view` (not cleared by this sensor). No real calibration was performed.
- `address-assignments.csv`: `record_id`; `address` (documentation IPv4); `asset_id`; `valid_from_utc`; `valid_to_utc_exclusive`. A join succeeds only if `valid_from_utc <= event time < valid_to_utc_exclusive`. No qualifying row means *unresolved*, not the most recent asset.
- `identity-events.csv`: `record_id`; `timestamp_utc` (excerpt’s original UTC time); `destination_asset`; `record_kind` (`4624-style` is a teaching analogue); `logon_type` (3 network, 10 remote interactive if present); `account`; `source_address`; `session_id` (nullable); `excerpt_scope`. An account label does not identify a person at the keyboard.
- `host-events.csv`: `record_id`; `timestamp_utc`; `asset_id`; `action` (as recorded in this authored scenario); `source_address`; `account`; `process` and `session_id` (nullable); `excerpt_scope`. An SMB-service entry is not an execution record.

The administrator note is in setup.md. Both supplied PCAPs are synthetic Ethernet/IPv4/TCP captures built offline, not real sensor exports. Original frame IDs restart at 1 in each source. Per-source decoded-fields files were actually generated by TShark; frame.time_epoch is raw POSIX seconds, not clock-corrected time. OP-B comparable time = raw time minus 2 seconds. Protocol and info columns are actual decoder outputs. Verbose output exposes application fields; Conversations is an actual CLI table, not a native GUI screenshot. execution.json records commands, exits, rebuild equality, overwrite refusal, file sizes and SHA-256. Current inventory hashes current deliverables; it does not claim independent approval.
