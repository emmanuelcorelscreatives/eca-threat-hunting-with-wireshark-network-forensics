# Data dictionary and evidence limits

`discovery-map.csv`: source address, attempted target, observed responding peer (unknown if absent), packet frame references and bounded observation. `address-map.csv` supplies fictional role assignments; packets alone do not prove system roles or human identity.

`identity-events.csv`: fictional unique record ID; original ISO timestamp without suffix plus explicit UTC zone; recording computer; Windows-shaped event ID; account; available source address/workstation; logon type; status/substatus; destination_field (blank = not supplied/not part of this excerpt); provenance. Blank does not mean zero or success. These are selected teaching rows, not exhaustive logs.

4771: Kerberos pre-authentication failure event at the domain controller. Code 0x18 means invalid pre-authentication information. 0x19 means additional pre-authentication required; do not combine it with 0x18 as bad-password failures. 4776: credential validation at the system authoritative for credentials; it may name source workstation, but does not identify a destination computer. 4625: failed logon at the recording computer; this designed row has status0xC000006D/substatus0xC000006A (failure/bad password). 4624: successful logon at the recording computer; type3 is network logon, not proof of an interactive human session. No event identifies an operator or establishes authorization.

`coverage.csv`: selected source windows and stated gaps. Fictional timestamps are intentionally ordered by design, not measured synchronized host clocks. Original timestamps are authoritative values for this worksheet; clock accuracy for real cross-source attribution is unknown. Do not invent adjustments or millisecond causal certainty.

`timeline-template.csv`: source ID, exact frame/event, original time/zone, clock uncertainty, observed fact, proposed relationship, confidence and unresolved gap. `asset-shortlist-template.csv`: attempted versus responding status, corroborated outcome, known coverage, unresolved question. `hypotheses-template.md`: observed/inferred/unresolved ledger and competing explanations.

`practice.pcap`: classic Ethernet PCAP with 23 complete designed TCP frames, no live traffic. Frames1–7 are discovery-style TCP445 probes; the map is supplied as prerequisite. Frames8–15 and16–23 are TCP389 LDAP anonymous bind sessions. Each LDAP request has empty name and empty simple authentication; result0 accepts anonymous bind, result48 rejects it as inappropriateAuthentication. A TCP port or server response does not prove an SMB service identity. TCP checksum validation is enabled in the execution check. No credential, ticket or NTLMSSP authentication is present. The packet filter matches four LDAP PDUs, not four account logons.


`case-evidence-inventory.csv`: source_id identifies a missing saved-case source; availability is not supplied; original_time_zone, coverage and clock_information are unknown; handling_restrictions states preservation/restricted-identity requirements, not a claim of actual sensitive data. `discovery-map-template.csv` uses the same schema as discovery-map.csv but has no observations. Availability: not supplied = absent input; unknown = cannot determine value; unavailable relationship = supplied fields do not support a match; not applicable = concept/field does not apply. Never convert any of these into zero events.

Confidence allowed values: observed_synthetic = direct field in this authored teaching input; tentative = proposed contextual relationship needing corroboration; unavailable = insufficient supplied fields; unresolved = question not answered. These labels never certify a real incident. `scope_classification`: potentially_involved identifies a system supported by supplied contact/event references; outside_known_coverage requires explicit source/coverage evidence, not absent response. APP-C is potentially involved as attempted-only and has unknown host outcomes, not outside packet coverage. `supporting_refs` carries filename+frame/event identifiers.

fixture-spec.json output schema: scope,epoch,packetCount,captureSha256,network,ldap,identityRows,timestamps,authoritativeSource. protocol-examples-spec.json output schema: scope,authoritativeSource,packetCount,captureSha256,kerberos,ntlmssp,correlation. Both are derived summaries; full input construction is in the corresponding executable generator. Timestamp values in worked files remain original source strings with UTC zone and explicit clock uncertainty. protocol-examples.pcap introduces a separate14-frame source and DC-LAB mapping. Confidence and relationship are distinct from a protocol result.

Coverage source IDs: PCAP explicitly identifies practice.pcap; PROTOCOL_PCAP identifies protocol-examples.pcap and has its own original UTC window10.450–12.620. Both are byte-construction windows, not real collection windows. LAB-CLIENT is included in the worked shortlist as observed initiating source with unresolved process ownership; no target-host authentication outcome is inferred on it.
