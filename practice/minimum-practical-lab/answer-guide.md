# Answer guide

1. OS and architecture depend on the learner's workstation. The narrated example is Windows 11 x64; choose the matching **current stable** official distribution and include Wireshark and TShark. Package selection alone is not evidence of successful installation. Do not supply a version manifest or capture-permission result: those checks belong to the next lesson.
2. One suitable workstation, both analysis tools, and authorized supplied offline captures are the minimum for required investigations. Opening saved packets is separate from collecting packets. Npcap and controlled capture setup are not prerequisites for File → Open; neither are a VM, paid service, cloud account, live malware, or a production-network connection.
3. The stated memory and storage figures are provisional until final case-pack sizes are known. An optional VM plan may require more memory.
4. Choose **File → Open**. With no file in the saved demonstration, there are no observed endpoints, frames, time windows, or findings to answer with.
5. **Optional synthetic fixture, actually decoded locally:** Both supplied formats contain six frames. The exported actual fields are in `practice.pcap.fields.tsv` and `supplemental-dns-baseline.pcapng.fields.tsv`. Client `192.0.2.10` sends queries to resolver `192.0.2.53`; frames 1/2, 3/4 and 5/6 are query/answer pairs for `lab-a.example`, `lab-b.example` and `lab-c.example`. Their A answers are `198.51.100.10`, `198.51.100.11` and `203.0.113.12`. The first timestamp is epoch 1737028800; the last is 1737028802.018, a 2.018-second span. These are designed synthetic values independently decoded from actual bytes, not historical case findings or proof that a learner opened them. A learner must report their actual displayed results; if inaccessible, use **unavailable; publication unverified**. DNS exchanges alone establish no compromise, user action, or real-host state. The exercise does not replace the later authorized case packs, which are outside this lesson's scope.
