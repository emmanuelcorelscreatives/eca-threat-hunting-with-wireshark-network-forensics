# Investigation worksheet

Question: For lab-win11-01 in this limited authored window, do DNS answers, separate outbound TLS sessions and independent host records support an unexplained callback? Test the approved device-management agent and other application behavior as alternatives. Repetition alone proves no C2 purpose.

1. Inventory both packet files and both CSV sources. Record exact hashes, origins, authorization, observation points, time ranges, endpoint mapping, original time zone, clock uncertainty, coverage and gaps. Distinguish the synthetic exercise from the unavailable narrated case.
2. Open the DNS source, apply `dns`, and pair questions and replies using transaction ID, name and endpoint/resolver tuple. Record the response frame, UTC time, status, every answer and TTL. Explain how caching, missing sides, several possible addresses or shared hosting could limit a real investigation.
3. Open the separate TLS source. Compare clocks and observation points first. Apply `tls`, then a destination actually present. Inspect the first handshake and its visible name without claiming hidden application content. Clear the TLS filter to inspect SYN starts and direction. Record six separate starts, peers, ports and durations from original frames. Explain why a single filtered row is not a session.
4. Use Statistics → Conversations → TCP to compare all six conversations and the two conversations to 198.51.100.20. Verify the Limit to display filter only state. Use an I/O Graph to find busy windows, then return to original packets to confirm starts; do not treat graph bins as check-ins. Record selected interval, filter, units, and at least one graph-window-to-frame link.
5. Construct a source-separated timeline: source file/frame or CSV row ID, original UTC time, observed or asserted field, proposed link, agreeing identifiers, disagreements and gaps. Preserve original times; do not manufacture clock corrections. Compare host source ports, destination ports/addresses, endpoint and the .010-second constructed difference. Explain H-A/H-B coverage and the missing candidate host entry.
6. Compare the benign baseline's actual owner/approval/role, destinations, names, conditions and limited window with candidate behavior. Explain why matching five-minute intervals do not establish the same software or permission. Test shared infrastructure and unrelated application behavior too.
7. Write a short brief with the specific question, source-backed observations, inference, alternatives, confidence, unknown encrypted content and host coverage, time-bound indicators, and a next request aimed at the weakest link. Keep harmless agent destinations separate from suspected indicators. Direct any containment proposal to the response owner with operational impact and urgency.

Assessment (20 points): source inventory and honest scope 3; DNS pair/TTL and changing answers 3; six packet-backed starts plus Conversations/graph distinction 4; source-separated host timeline and gap 4; approved-agent comparison and alternative explanations 3; bounded brief, indicators and next request 3. A conclusion of inconclusive can receive full marks when justified. Fabricated packet/process attribution, hidden TLS commands, invented clock fixes or repetition-as-proof require correction.
