# Data dictionary

`dns.pcap`: twelve authored Ethernet/IPv4/UDP/DNS packets, six questions and six responses. `dns-fixture.json` is its original design input. Answers contain A records, TTL 60, and NOERROR. Frame time is authored UTC; it is not an observation of a real resolver. Packet references must include this filename.

`tls.pcap`: 132 packets in six TCP streams. Actual Python/OpenSSL TLS 1.2 handshakes, encrypted application records and close alerts were generated in memory, then wrapped in checksum-valid authored transport with synthetic addresses, TCP sequence numbers and times. No live capture or production process ran. TLS plaintext and session secrets are not supplied; the exercise asks for visible metadata, not decryption. SNI is an observed handshake field in these TLS 1.2 sessions; it is a lead, not proof of application purpose or DNS lookup use. Raw TCP counters and checksums were independently checked. `tls-fields.stdout.txt`, `tls-starts.stdout.txt`, `tls-conversations.stdout.txt` and other command logs record decoder output. The root-user warning in stderr is retained provenance, not a packet defect.

`process-network.csv`: five authored host events with IDs H01–H05. `recorded_at_utc` preserves the original scenario time; `endpoint_id` identifies the scenario host; `process_name` and `pid` are host assertions; source/destination IP and port allow bounded connection matching; `event_kind` is connect_attempt, not success. `source_id` names HOST-EXCERPT-01; `coverage_id` H-A/H-B gives the coverage window described in setup. `origin` explicitly marks independent synthetic host metadata.

`benign-agent-baseline.csv`: one comparison record. Its approval, owner, endpoint role, destination, domain and time fields are authored assertions available for this exercise, not independent validation of real software. Compare actual values and coverage; do not substitute a familiar process name for approval. Refer to baseline records by row number plus identifying fields.

`replay-records.json`/`rebuild_capture.py`: approved capture bytes, SHA-256 checks and safe exclusive directory creation. `execution-proof.json`: actual rebuild, overwrite refusal, raw TCP bookkeeping and command receipts. `tls-generation-receipt.json`: six session origins and encryption parameters. Native receipts bind screenshots to source capture hashes; they do not broaden Linux evidence into a Windows execution claim.
