# Setup and actual exercise

Use Python 3 and TShark (`python3 --version`, `tshark --version`); Wireshark 4.4 is the native reference here. Work only on an authorized local copy. No network interaction is required or performed by the builder. Preserve before.pcap and after.pcap; compute `sha256sum before.pcap after.pcap` (on Windows use `Get-FileHash`).

1. Run `python3 verify.py`. It checks exact decoded fields, synthetic record references, all filter memberships, zero malformed packets, and a fresh temporary byte-identical rebuild of both files. It verifies a second builder execution refuses to overwrite the first output. It prints actual results; compare execution-proof.json.
2. Optionally rebuild elsewhere: `python3 offline-builder.py --spec before-spec.json --output rebuilt-before.pcap` and the analogous after command. Existing outputs are refused. Compare SHA256 with the originals; do not overwrite supplied files.
3. Open before.pcap in Wireshark with File > Open. Clear the display filter. Use Statistics > Capture File Properties: note captured versus displayed counts and earliest/latest recorded times. Open after.pcap separately and repeat. These are packet bounds, not monitoring-duration claims. Set View > Time Display Format > UTC Date and Time of Day if desired. The training collection register supplies precise UTC bounds.
4. On before.pcap, apply `ip.addr == 192.0.2.10`, inspect frames1–2 and Statistics > Conversations > UDP. Compare source/destination ports, direction and surrounding traffic. Clear the filter and confirm all four packets reappear. The Conversations “Limit to display filter” control changes its scope: record its state. If disabled, compare the whole file; if enabled, compare only matching traffic. Never treat an empty filtered screen as a capture gap.
5. Apply `ip.addr == 192.0.2.20` to each file. Before matches frames3–4, after matches frames1–2 (frame numbers are file-local). Read packets as datagrams only: payload strings are fictional labels, not execution/transfer proof. Inspect protocol details for addresses/ports/timestamps. UDP traffic alone proves neither delivery nor purpose.
6. Read capture-register.csv, collection-records.csv, approved-activity.csv and asset-records.csv. Match the exact host, peer, ports, direction, job identifier and bounded time for the distracting lead. Distinguish this supplied independent scenario context from packet facts. Do not reuse its harmless explanation for another endpoint.
7. Complete the worksheet and your conditional real-case template. If any original Project7 material is absent, request it and preserve the inconclusive result.

GUI names may vary across OS versions; native reference pictures show actual Linux controls, not Windows verification. TShark commands used by verify.py are also executable individually: `tshark -n -r before.pcap -Y 'ip.addr == 192.0.2.10' -T fields -e frame.number` and `tshark -n -r after.pcap -q -z conv,udp`. For Windows shells quote the filter with double quotes. `tshark -r before.pcap -Y _ws.malformed` should output nothing. A valid empty result is distinct from a failed command; verify.py checks return codes.
