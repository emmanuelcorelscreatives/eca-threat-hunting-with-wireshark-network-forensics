# Synthetic resource dictionary

`executed-fixture-spec.json` is the actual version-1 input used for the deterministic build. `fixture-spec.json` is a byte-identical alias in the assembled kit; both have SHA-256 `7cc31e96ddc6d78c4d75c2b3973b5c5d54c7d9aa509f728aad014861bab06e95`. Do not assume a separately obtained alias is identical without checking it. `offline-builder.py` is the packaged offline builder, not the earlier proposed `builder.py`. It sends no packets but **overwrites its output path**.

The specification requires `synthetic: true` and timestamp-ordered `events`. Each event has a UTC `timestamp`, `kind`, and documentation-network IPv4 `src`/`dst`. DNS events use `sport`, `dport`, reserved `.test` `name`, and `transactionId`; answers also use `answer`. TCP events use ports, `flags`, `seq`, and `ack`. ICMP events use `identifier`, `sequence`, and harmless `payloadText`. These are authored inputs, not independently observed asset activity or proof that a protocol was decoded.

The assembled `practice.pcap` is the generated Ethernet/IPv4, microsecond-precision PCAP: 1,008 file bytes, SHA-256 `e10afad728c59c439fda842c80ef7b18f366c20922299ea3919b558f2ac09337`. It is delivered unchanged with this complete companion lab. A PCAP file's size includes capture-file overhead; hierarchy Bytes and `frame.len` are not file-content or application-payload measurements.

`capture-context.csv` is **authored scenario metadata, not a host log or packet-derived inventory**. `asset_id` is a synthetic label; `ip` is its documentation address; `role` and `expected_services` are proposed operational context, not proof of authorization. `capture_point` describes the authored workstation-side view; `start_utc` and `end_utc` bound the designed window; `coverage_limits` states what cannot be inferred. Semicolons separate phrases within a CSV field. All four rows describe the same limited scope. The capture cannot establish a process, user, traffic purpose, or network-wide absence.

The packaged `*.stdout.txt` files are results of the specified read-only **Linux TShark 4.4.0** and `capinfos` runs, not Windows or GUI transcripts: `capture-info` describes the PCAP; `all-frames` lists decoded fields; `protocol-hierarchy` reports an empty-filter hierarchy; `ip-conversations` and `tcp-conversations` report peers and frame bytes; `malformed` contains no frame numbers matching `_ws.malformed`. Corresponding stderr files record a root-execution warning for TShark; students should not run as root. Empty output for that one malformed filter is not a checksum audit or proof of complete capture coverage. `frame.time_utc` in `all-frames` is a human-readable UTC string, **not ISO 8601**; `frame.time_epoch` is seconds since the Unix epoch. Nine printed fractional digits do not increase this PCAP's microsecond timestamp precision. `frame.time_iso8601` is unsupported in the pinned build and must not be substituted into these commands.

`decoded-fields.stdout.csv` and its execution receipt provide actual additional Linux dissector fields: DNS transaction IDs/response flags, TCP flags/raw sequence/acknowledgment/payload lengths, ICMP types/identifier/sequence, and explicitly enabled IP/TCP/UDP checksum-status fields. Status value 1 denotes Good in this Wireshark build; blank fields mean not applicable, not an observed good checksum. The command does not claim all possible checksums or collection coverage were tested.

`native-*.png` are actual unmodified native Linux Qt Wireshark 4.4.0 application screenshots from an isolated offline Xvfb session. `native-execution.json` binds original paths/roles and hashes to the unchanged PCAP. `native-independent-approvals.json` identifies exact independent role-limited passes; neither artifact grants main-video visual approval. `host-platform.json` identifies the actual Linux host and binary. The lecture's Windows identity is unchanged and no Windows execution is invented. Current inventory is separate from dated historical execution inventories; those remain evidence of their original snapshot only.
