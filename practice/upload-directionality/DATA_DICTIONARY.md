# Evidence dictionary

`practice.pcap`, identical `upload-directionality-synthetic.pcap`: synthetic documentation-address HTTP/FTP training traffic. `fixture-spec.json` is a byte-identical copy of executed-fixture-spec.json, consumed by offline-builder.py through generate_fixture.py. Reserved names/addresses are training labels, not real attribution. Original lecture supplies no capture.

`encrypted-session.pcap`: actual author-owned local loopback TCP/TLS1.2 session, no address rewriting. Both endpoints127.0.0.1; ports distinguish direction. `encrypted-session-application-receipt.json` is an endpoint receipt separate from packet-only evidence. No keys or controlled collector private directory is delivered. The session is not regenerated by the offline synthetic builder.

`frame.len`/conversation bytes: captured packet units including headers. `tcp.len`: TCP payload bytes, including TLS framing when applicable. `tls.record.length`: encrypted record bytes excluding its5-byte header, including cryptographic overhead; not protected-file size. HTTP Content-Length describes intended HTTP body length. FTP PORT specifies data listener address and high*256+low port. STOR requests client data toward server, RETR requests server data toward client; verify separate flow rather than assuming initiation direction.

`all-frames.*`, `capture-info.*`, conversation/protocol/malformed outputs: actual historical synthetic decoding. `http.*`, `ftp.*`, `encrypted*.*`, current-cli-execution.json: current actual command outputs, with explicit TLS Decode As. Empty malformed output means this decoder reported no malformed frames; it is not proof every packet is complete. Stderr root warnings are recorded, not decoder failures. assembly-manifest.json is historical and is not final inventory. native-gui-execution.json lists source-bound actual GUI captures; independent receipts determine approved evidence. Current final inventory binds delivered bytes.

The unqualified pending-encrypted-session purpose in fixture-spec.json and executed-fixture-spec.json is historical metadata of the HTTP/FTP-only component. Those exact executed specifications are retained for deterministic replay. The pending status is superseded at the complete-kit level by encrypted-session.pcap and its separate endpoint receipt; neither specification purports to generate that real TLS capture.
