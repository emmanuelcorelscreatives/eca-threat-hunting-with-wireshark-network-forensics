# Relationship worksheet

1. Record source filename, SHA-256, origin, capture scope, local tool versions and the UTC packet window. Explain why this synthetic fixture is not evidence of a real Windows incident.
2. In Conversations record all three IPv4 pairs, total and directional packets/bytes, relative start and duration. State why packet counters do not establish file transfer.
3. Apply `smb2`, then `smb2 && ip.addr == 192.0.2.21`. Record both displayed counts and frames. If the view is empty, check filter, file, decoding and coverage before drawing conclusions.
4. Build a row for each Tree Connect pair: stream/tuple, request frame/time/path, response frame/time/status, Message ID and Tree ID. Match directions within the same stream. Explain why a request alone does not demonstrate success.
5. Compare each peer, share and request time with asset-inventory.csv and approved-activity.csv. Use three columns: packet observation; supplied context; remaining question. Label TeamDocs role-aligned, ADMIN$ activity-aligned, or ProjectDrop unexplained only when your evidence supports it.
6. Explain at least two benign explanations for the unexplained peer, such as incomplete inventory, temporary collaboration or undocumented support. Identify records needed to distinguish them. Do not relabel unexplained as unauthorized or malicious.
7. Explain why successful synthetic Tree Connects prove neither file transfer, user identity, process execution, intent nor real authorization. State what encryption or missing sessions would prevent you seeing. Preserve the lecture's method-only/no-case qualification.
8. For an optional authorized local follow-up, select your own bounded capture point and time window, preserve the original, create a working copy, document asset ownership, and repeat the three-column comparison. Stop when visibility, authority or context is insufficient. This kit does not include or claim completion of that learner exercise.
