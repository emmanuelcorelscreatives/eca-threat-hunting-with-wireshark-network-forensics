# Split, Merge and Inspect Captures — executable synthetic lab

This offline lab supplements the unchanged lesson. These are authored packets, not the unavailable narrated capture and not observations from real sensors. No packets are sent. Actual verification used Ubuntu Linux, CLI tools 4.2.2, with separate native Wireshark GUI 4.4.0. The original lecture explains Windows installation paths; this package supplies a cross-platform Python replay using capinfos, editcap, mergecap and tshark on PATH. Linux execution and screenshots do not prove Windows execution.

Download the complete package preserving all subdirectories. Install Python 3 and Wireshark command-line tools. From this directory run `python3 replay.py NEW_OUTPUT_DIRECTORY` (Windows: `py replay.py NEW_OUTPUT_DIRECTORY` with Wireshark added to PATH). Choose a directory that does not exist. The program refuses an existing output directory. It rebuilds the ten-frame master from fixture-spec.json using offline-builder.py; creates originals/sim-sensor-A.pcap and originals/sim-sensor-B.pcap; copies them unchanged to working; executes actual count split, exclusive-stop time cut and merge; records exact argv, exit code, stdout and stderr in commands.json and execution.json. It never reads or modifies an unrelated user capture. On failure inspect commands.json; retain the failed directory and choose a new one after correction.

The supplied executed/ directory is the actual author run. Run your own replay to a different directory and compare packet counts and bytes. Absolute recorded paths describe the author host; resolve delivered paths relative to this package. Pcapng container bytes can vary between tool versions, so compare measurements and packet records rather than assuming a fresh merged-file hash matches. The original capture hashes in executed/execution.json identify the exact delivered originals.

Open executed/working/merged.pcapng through File > Open. Apply `udp`, select a packet and expand User Datagram Protocol in Packet Details; examine Packet Bytes. For an A-only example match the EC-L4-A01 payload at second00 to original A frame1. For B-only match EC-L4-B03 at second04 to original B frame3. Reopen the named originals and compare recorded time, endpoints, ports and full bytes. Open any working/chunks file and repeat a reference. `packet-reference-key.csv` supplies mechanically matched time/endpoints/payload candidates, not an assertion that the learner has inspected them or that it proves full-packet equality. Overlap rows have two possible merged frames; leave attribution unresolved. Delivered native PNGs document actual author GUI observations; they are separate from your own verification.

Fill the three CSV templates from measurements, never copied expected values. Real-case substitution requires authorization and known collection restrictions; never overwrite received originals.
