# Student investigation workbook

Do not open the instructor key until your provisional answer is complete. Use PCAP-1 original frame numbers, RECORDS-1 IDs, UTC timestamps and explicit uncertainty for every claim. Preserve originals; exported subsets may renumber frames, so retain original references and transformation notes.

1. Record source filename, hash, capture point, coverage window, file format, clock uncertainty and gaps. State which completeness properties are unknown. Compare Capture File Properties, Protocol Hierarchy, Endpoints, Conversations and I/O Graphs before filtering.
2. Inventory the assigned workstation, both external candidates and internal peers. Shortlist each outbound peer alongside a benign hypothesis: monitoring, backup/synchronization or update. Document why each hypothesis fits or fails asset, ownership and schedule evidence. Include the other workstation as background rather than attributing it to the assigned asset.
3. Apply `ip.addr == 192.0.2.10`. Clear to confirm wider captured context. Inspect DNS and compare the answer with subsequent contact. Distinguish observed name resolution from application ownership or causal proof.
4. Select packets and use Analyze → Follow → TCP Stream; return to packet context. Report visible placeholders and connection metadata. Never claim a command, user, file, actual encrypted content or sensitive data. Measure comparable SYN starts for the repeating peer, not every packet. Calculate gaps and compare OWN-1.
5. Compare internal peers. Separate unanswered attempt, completed handshake, opaque payload and absent file-operation/endpoint-execution evidence. Check OWN-2 and MAP-1 before linking packets to the asset. ID-1 does not identify an operator or transaction. Discuss ±2 second uncertainty and other unobserved systems.
6. For the unexplained outbound peer compare directional frame-byte counters, TCP payload bytes and possible unique application bytes. Note retransmission/overhead caveats. Relate internal and outbound times without asserting causation. Test backup/synchronization against missing owner/transaction evidence. Do not equate observed bytes with data loss.
7. Deliver a timeline (source, original frame/record, original timestamp, observation, separate interpretation), evidence register (claim, filter, source reference, counterexample, confidence, missing evidence), provisional finding, observed/possibly affected/unseen assets, strongest benign or mixed explanation and narrow next action. Request exact process/socket, file audit and destination ownership records for workstation-A and the relevant interval. State disruption risk; do not claim containment occurred.
8. Clear filters and reopen each cited original frame. Check time, direction and stream; retain source references even if screenshots are attached. Rate confidence per claim. Stop widening scope after answering the bounded question or exhausting supplied sources; request authorized records rather than guessing. Prepare to defend the finding in the next lesson.

Suggested register columns: source ID | frame/record | UTC ± uncertainty | observation | interpretation | reproducible filter | alternative | confidence | next evidence. An unresolved or mixed finding is acceptable when supported.
