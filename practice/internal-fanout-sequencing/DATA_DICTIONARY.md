# Data dictionary

All input is synthetic. scenario.json captureDesign declares intended windows/gap; these are NOT collector evidence. flows supplies capture filename, unique flow ID, client/peer documentation IP, client/server TCP ports, firstSMB2DesignUtc in UTC. The implemented fixed profile emits14frames per flow: handshake3, Negotiate/Session Setup/Tree Connect request-response6, client ACK1, orderly FIN closure4. TCP payload lengths determine seq/ack and checksums. build_fixture.py accepts the scenario schema and writes offline only; check_fixture.py independently parses bytes, TCP continuity/checksums, SMB framing/commands/shares and first times. No package or network access is needed. No real passwords are present; session responses mark the modeled guest flag. It is a decoder fixture, not a production authentication implementation.

asset-inventory.csv supplies seven synthetic asset/address/hostname/role/owner mappings and validity UTC intervals. job-runs.csv supplies configured and owning source, planned and actual times and synthetic scheduler provenance. job-targets.csv joins job IDs to target asset IDs. Inventory and jobs remain contextual assertions. No independent execution, permission or clock alignment is proved by these rows.

execution.json and referenced actual stdout files bind structural validation, deterministic rebuild and native TShark4.4 decoding to exact capture SHA256. native-execution.json describes actual isolated Linux GUI actions and source PNG hashes; native reviews scope only to those actual views. Peer timeline is derived from .110 SMB2 first occurrences, not bytes or packets. Expected answers are checked against actual generated files. Original proposals under the maintenance tree are historical; only this folder and its current inventory form the deliverable.
