# Data dictionary and scope

All addresses are documentation-only IPv4. `192.0.2.10` is the fictional scoped workstation; `.11` is a different fictional administrative source. `198.51.100.40` is the fictional managed sync gateway and proposed packet peer; `.50` is a fictional direct backup repository. These roles come from **scenario metadata**, not DNS or authentication observed in packets. No production identifiers, credentials or personal records are present.

`synthetic-transfer-spec.json` is the supplied offline builder's version-1 synthetic JSON input. Each ordered `events` item has UTC `timestamp`, `kind: tcp`, `src`, `dst`, TCP `sport`/`dport`, `flags`, `seq`, `ack` and optional UTF-8 `payloadText`. SYN and FIN each advance TCP sequence space by one; ACKs account for the marker lengths. The builder authors one link, not comprehensive host capture coverage, a network transmission or an application protocol. Generated Ethernet/IP/TCP frame lengths and Wireshark conversation counters require decoder verification.

`synthetic-activity-records.csv` is **fictional scenario metadata, not packet-derived logs**. UTF-8 CSV with header; all fields are strings. `record_id` is a stable join key; `record_type` identifies inventory, plan, policy or approval; `asset_ip` and optional `peer_ip` define the record's covered endpoints; `window_start_utc` and `window_end_utc` are inclusive synthetic applicability windows, not packet timestamps; `owner_team` is a fictional contact role; `reference` names a fictional job, policy, task or asset; `scope_and_status` states what the record covers; `caveat` names what it cannot establish. Empty peer means inventory has no authorized destination. No row is a backup-run, sync-account activity or host task-execution log. A record for another source or peer cannot be silently joined to the packet conversation.
