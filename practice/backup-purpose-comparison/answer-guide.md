# Answer guide — measured toy fixture and bounded purpose assessment

Actual delivered TShark output and builder execution receipts establish 15 frames, one TCP conversation, 2025-01-16 12:00:00.000000–12:00:00.280000 UTC, duration 0.28 seconds. Frame 1 is SYN, 2 SYN/ACK, 3 ACK; outbound payload frames 4, 6, 8 carry ACADEMY-A, ACADEMY-B, ACADEMY-C (9 bytes each); frame 10 returns OK (2 bytes). Frames 12–15 close with FIN/ACK, ACK, FIN/ACK, ACK. The outbound direction has 8 packets/459 frame bytes and return direction 7 packets/380 frame bytes, total 839 captured frame bytes. The classic PCAP file is 1103 bytes including record/file headers. These are different units: 27 outbound and 2 return TCP payload bytes are not unique file bytes or a sensitive-data-loss estimate. Confirm counters in tcp-conversations.stdout.txt and individual rows in decoded-fields.csv. The short fixture demonstrates comparisons, not transfer scale.

No matching job run or alternate route is supplied: backup remains unresolved; request covered asset, expected intermediary/path and run record from the backup owner. Ask the administrative owner for a separate source/destination/task-window approval and host task linkage. These CSV entries are fictional business metadata, not packet logs.

A defensible answer is purpose unresolved. A surface sync match is weaker than a documented connection-specific authorization; backup topology or another approval could change the assessment. An ACK is not upload authorization; familiar peers, working hours and labels establish no intent. A missing log does not prove exfiltration. Encryption, clock uncertainty, record retention and capture point can limit real investigations. The packet layer states only the observed pair/window/direction and visible synthetic markers. The business layer states the exact matches/conflicts above. The unknown layer names account, approved activity and content identity. Request the smallest useful owner record, share only needed details, and keep observed bytes separate from sensitive-data loss. No real data-loss confidence can be assigned from this toy.
