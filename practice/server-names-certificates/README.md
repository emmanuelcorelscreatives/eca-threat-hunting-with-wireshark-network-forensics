# Use Server Names and Certificates Carefully — executed supplemental lab

This separately authored Academy exercise preserves the saved no-case-capture lecture. Actual controlled OpenSSL sessions on the author’s Linux loopback provide TLS 1.2 and TLS 1.3 handshake evidence. They are not the lecture’s historical incident. No Internet access or real accounts were used. Both endpoints share 127.0.0.1; identify direction by ports and stream, not IP alone. UTC epoch times are in the manifest. Private keys and decryption secrets are not supplied.

Open `tls-metadata-supplement.pcapng` in Wireshark 4.4 (File → Open). Keep an original and work on a copy. Apply `tls.handshake.type == 1`; expand Transport Layer Security → Handshake Protocol: Client Hello → Extension: server_name. Record frame/time, full endpoint tuple, stream and advertised DNS name. Then apply `tcp.stream == 0` and `tls.handshake.type == 11`; inspect the same stream’s readable Certificate subjectAltName. Expand the TLS certificate tree and compare its DNS names with the advertised name. Use `tls.handshake.type == 2` and the supported_versions extension to establish TLS 1.3 in stream 1: legacy 0x0303 is insufficient. Use each filter separately or combine with parentheses and `&&`.

`tls-metadata-supplement-manifest.csv` contains actual packet fields for every captured frame. `handshake-details.txt`, `capture-info.txt`, `malformed.txt`, `checksum-status.csv`, and `execution.json` are actual executed CLI outputs/provenance. An empty malformed output establishes only that this decoder found no malformed frames; file SHA establishes byte identity, neither proves packet checksum validity. Loopback offload can yield reported bad/unverified checksums; inspect the separate status output and do not call them network corruption. Sanitized generation client logs omit session master keys/resumption PSKs. Generation client logs include the controlled client’s configured-CA chain verification (hostname verification was not requested); this is endpoint evidence, not a packet-only trust inference.

For this supplied capture, TLS1.2 stream 0 ClientHello is frame 4 and readable ServerHello/Certificate is frame 6. TLS1.3 stream 1 ClientHello is frame 21 and ServerHello is frame 23. Stream 0 ServerHello legacy version is 0x0303; the controlled completed TLS1.2 full handshake presents shop.academy.test and cdn.academy.test in SAN. Stream 1 selects 0x0304 via supported_versions; its certificate is encrypted and not readable without secrets. ClientHello SNI in both streams is shop.academy.test. Absence of a readable certificate is a visibility limit, not proof no certificate was exchanged. Follow each whole stream to verify SYN setup and directions; do not map certificates across connections merely because destination IP matches.

No ECH, QUIC, TLS1.2 resumption, late-start or one-way case is implemented here. The eight scenario cards remain hypothetical reasoning exercises for those alternatives; their labels are not packet stream IDs. No packet evidence here establishes an encrypted application URL, completed visit, maliciousness, user identity, or client trust decision.

Run `python3 rebuild_capture.py NEW_PATH.pcapng` for exact offline byte reconstruction; output must not exist. This is an archive reconstruction, not a new live capture. Run `python3 build_tls_fixture.py NEW_DIRECTORY` only on your authorized Linux loopback, with Python3, OpenSSL3 and dumpcap permissions. It actually generates new disposable keys, full TLS1.2 and TLS1.3 sessions, certificate and pcapng; new ports, timestamps, random TLS bytes and certificate are expected, so frame references/hash are specific to the supplied capture. Do not reuse this answer key automatically for a new capture. No private key survives its temporary directory. The builder refuses an existing output directory. Verify with `tshark -r tls-metadata-supplement.pcapng -Y 'tls.handshake.type == 1 || tls.handshake.type == 11' -T fields -e frame.number -e tcp.stream -e tls.handshake.extensions_server_name -e x509ce.dNSName`; use `capinfos -c -a -e -u tls-metadata-supplement.pcapng` for count/start/end/duration.
