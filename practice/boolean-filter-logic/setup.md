## Apply, inspect, and cross-check

Open `practice.pcap` with **File → Open**, check your installed Wireshark version, apply the worksheet's exact expressions, and inspect source, destination, ports, flags when relevant, and time for candidate packets. The quoted time literals were accepted in the recorded UTC-context 4.4.0 Linux and Windows tests; verify the interpretation on *your* installation and compare its time-display setting with UTC. A green/accepted filter means it parses, not that it expresses the question you intended. If rejected, inspect operators, quotes, parentheses, version, and time interpretation. Use **Clear** beside the display-filter bar to widen the view. Never turn an empty view into a claim that no traffic occurred.

Optional read-only POSIX/Linux comparisons, from the kit directory, are:

    TZ=UTC tshark -r practice.pcap -Y 'ip.addr == 192.0.2.10' -T fields -e frame.number
    TZ=UTC tshark -r practice.pcap -Y '((ip.src == 192.0.2.10 && ip.dst == 198.51.100.20) || (ip.src == 198.51.100.20 && ip.dst == 192.0.2.10)) && (tcp) && (tcp.port == 443) && frame.time >= "2026-01-01 12:00:00" && frame.time < "2026-01-01 12:05:00"' -T fields -e frame.number
    tshark -r practice.pcap -T fields -E header=y -e frame.number -e udp.srcport -e udp.dstport -e tcp.flags.str

These are learner commands, not a claim that each *shell spelling* appears verbatim in the execution records; the corresponding filter/extraction arguments and UTC-context checks did run. `mktemp`, `sha256sum`, and `TZ=UTC` assume a suitable POSIX shell; the independently recorded Windows CLI tests are real, but these POSIX shell commands are not Windows instructions. The source-built Linux 4.4.0 inventory found `frame.time_iso8601` unsupported; use the executed `frame.time_utc`/`frame.time_epoch` fields instead.
