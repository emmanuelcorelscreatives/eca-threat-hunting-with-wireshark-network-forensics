# Troubleshoot decryption expectations: actual Academy lab

This supplementary fixture contains five **actual controlled loopback TLS exchanges**, collected on Ubuntu 24.04 for the Academy. It is separate from the original lecture's no-file demonstration and from any historical incident. The original lecture is unchanged. Use only these disposable training secrets and captures in an isolated profile. The private key and secret log are intentionally supplied lab inputs, never reusable credentials. Real case secrets and decrypted derivatives require restricted handling.

Download the complete folder and keep relative paths. Required: Python3 for offline replay; Wireshark/TShark4.4 with TLS support. RSA-key decryption additionally requires a build with GnuTLS. The actual Linux4.4 build used here lacks GnuTLS; its log controls execute, while the additional RSA control was actually executed on system TShark4.2.2 with GnuTLS. See version and execution receipts. Do not mistake either for Windows execution.

Open `tls-troubleshooting-cases.pcapng`:75 frames, TCP streams0–4 corresponding to A–E. `case-manifest.csv` supplies ports and provenance. Dynamic ports are deliberate. For command-line inspection pass each `-d tcp.port==PORT,tls` using60529,50335,59647,36463,56793. In the GUI, Analyze → Decode As may be needed, especially late-start C. Assign each corresponding TCP port to TLS. Each case also has its own A–E capture. The complete C/D controls demonstrate what the deliberate omissions conceal; do not confuse control frame numbers with combined-capture frame numbers.

Start with an empty TLS log preference. Inspect scope before filtering; use `tls`, then clear it to see omitted start or TCP gaps. In Edit → Preferences → Protocols → TLS, inspect `(Pre)-Master-Secret log filename`. Empty means no selected log; a selected path alone proves neither a match nor a nonmatch. Select `session-secrets.log`, apply and compare the SAME stream and frame references. This log contains C and D only, deliberately no A or B secrets. Check supported_versions in A/D ServerHello; legacy0x0303 alone does not establish TLS1.2. C's negotiated version is unavailable in the late derivative and comes only from its separately supplied complete control.

For RSA E, the TLS_RSA_WITH_AES_128_CBC_SHA suite0x002f and ClientKeyExchange are captured. Import `lab-server-rsa-private.pem` into RSA keys in a GnuTLS-enabled Wireshark build. This deliberately obsolete isolated compatibility example is not a recommendation to weaken a real connection. The key does not decrypt A's TLS1.3 or B's ECDHE session. Clear imported keys and log after the exercise.

Run `python3 rebuild.py NEW_DIRECTORY` to replay exact supplied bytes offline. It refuses an existing output directory and never collects network traffic. current-kit-inventory.json identifies every distributed file except itself. Compare capture and secret provenance before applying secrets. `execution.json` and named stdout/stderr are actual executed checks; their absolute maintenance paths describe this validation machine, so replace them with your local paths when repeating.
