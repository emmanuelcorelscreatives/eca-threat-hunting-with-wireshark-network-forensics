# Synthetic fixture dictionary

Each JSON file is an independent version-1 specification for the supplied offline builder. `synthetic: true` is mandatory. `fixtureId`, `purpose`, `scope`, `observationPoint`, and `sourceLessonProjects` are **authoring metadata**, not packet-derived facts; the builder ignores them. `events` is an ordered list. `timestamp` is an explicit UTC ISO-8601 time; `src` and `dst` are documentation-range IPv4 addresses. No event represents a real collector.

For `kind: tcp`, `sport`/`dport` are ports, `flags: PA` means PSH and ACK, and `seq`/`ack` specify authored TCP byte positions and the next peer byte expected. The four TCP payload lengths in event order are 14, 15, 15, and 14 bytes; their specified sequence and acknowledgment values advance accordingly. No SYN or FIN is authored. For `kind: udp`, each `payloadText` becomes one datagram body. `udp.length`, if displayed, includes its eight-byte UDP header. `icmp-echo`/`icmp-reply` use `identifier`, `sequence`, and matching payload text solely as adjacent, different-endpoint context. All text payloads are synthetic UTF-8; the application-like labels are not identities or proof of processing.

Delivered captures are tcp.pcap and udp.pcap in classic PCAP format. There is no PCAPNG conversion requirement. The TCP and UDP specifications are independent and each decoder assigns stream 0 locally. cli-execution.json records actual commands; *-frames.stdout.txt gives observed frame fields, *-follow-ascii.stdout.txt and *-follow-hex.stdout.txt give decoded contributions, and *-info.stdout.txt gives file counts and times. Execution manifest hashes bind the exact delivered files. A Follow Stream index belongs only to its open capture.
