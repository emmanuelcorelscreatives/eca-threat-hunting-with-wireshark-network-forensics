**Authored metadata versus decoded evidence.** `packet-manifest.csv` has 20 rows. `planned_event_id` is authored JSON event order; `observed_frame` is deliberately blank. `role`, `notes` and intended `protocol`, `src`, `dst`, `sport`, `dport`, `method`, `uri` and `syn_value` are scenario design, not independently observed findings. An empty authored method/URI means no HTTP request was specified in that event; an empty SYN means no TCP header was specified. The builder writes one frame per event, and the supplied `all-frames.stdout.txt` supplies the actual `frame.number` and decoded fields for **this exact file**. Verify their correspondence before using a frame reference elsewhere; keep learner GUI observations in separate notes rather than changing the preserved CSV.

**Scenario.** Documentation-only `192.0.2.10` is the authored client, `192.0.2.53` the DNS server, `198.51.100.80` the HTTP endpoint, and `203.0.113.44` the port-443 TCP endpoint. `training.academy.test` is the authored DNS question and HTTP Host. The decoded DNS answer in frame 2 advertises `198.51.100.80`. Plain HTTP on port 80 permits request-field practice without TLS: decoded requests are frames 6 (`GET /reports/report.csv?rev=1`), 11 (`POST /status/reporting.txt`) and 16 (`GET /public/manual.pdf`). Their labels—report candidate, incidental substring and benign extension control—are teaching assumptions, not evidence of an investigation's true relevance. Frames 18–20 contain only the authored port-443 TCP handshake, with no application payload. No HTTP response or connection closure is asserted.

**Measurement vocabulary.** `capture-info.stdout.txt` reports 20 packets, 1,697 PCAP file bytes, 1,353 bytes of frame data, and microsecond PCAP timestamp precision. The executed export's `frame.time_epoch` is decimal Unix-epoch seconds; `frame.time_utc` is human-readable UTC text, **not ISO 8601**. This pinned build's inventory does not support `frame.time_iso8601`; no successful use of that field is claimed. `frame.len` and `frame.cap_len` are frame and captured-frame lengths (equal for each row in the supplied export); `tcp.len` is TCP payload length. `tcp.seq_raw`/`tcp.ack_raw` are raw numbers, whereas a relative-sequence GUI setting may display other numbers. `tcp.payload` on the three requests contains HTTP request bytes, not the requested CSV/PDF file's contents. `http.file_data` and `http.response.code` are blank throughout the supplied export. `linux-command-16.stdout.txt` directly exports repeated `tcp.port` occurrences and per-packet `tcp.flags.syn`. The count filter and SYN-presence/value filters were separately executed on both decoders and corroborated by the exact Windows GUI review receipts.
