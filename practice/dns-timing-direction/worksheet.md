# Investigation worksheet

**Hypothesis:** Repeated DNS exchanges might align with host activity and contain candidate visible text; neither observation alone proves a channel or exfiltration.

1. Record PCAP filename, actual collection point, window, timestamp display format, visible sides, verified host/address assignment, and whether the source is synthetic. Record host-log time zone and measured clock offset—or `unmeasured`; never adjust clocks to fit a story.
2. In Wireshark use `dns`, then the case-host filter from setup. Record each question’s name and type. Pair possible requests and replies by endpoints, name, DNS identifier, and time, not row proximity. Mark unseen replies `unobserved`, not failed. Compare retransmission indications with those same fields; distinguish retries, duplicate observations, and separate requests.
3. Populate `dns-exchange-worksheet.csv` using **decoded packet references**, not fixture event indices. Give each distinct candidate request a row; mark retry and repeated-label rows. Record precisely which variable label or labels were counted, excluding fixed `check.academy.test` and separators. Count candidate answer strings separately only if visible; do not count whole frames or A-address text as candidate messages.
4. Open **Statistics → I/O Graphs**. Compare `dns && ip.addr == 192.0.2.10 && dns.flags.response == 0` with the corresponding `dns.flags.response == 1` series. Start at a one-second interval; zoom to 100 ms if needed and inspect underlying pairs. A broad interval can conceal gaps. A Bytes graph includes overhead and possibly retries or responses: it is not a content total.
5. Compare packet times with the separately authored `host-events.csv`. With no measured clock offset, report possible overlap rather than an ordered cause. Consider approved checks and service retries; this metadata does not identify a DNS-initiating process.
6. Complete `case-analysis-template.md`. Separate cited observations, inference, unknowns, confidence, and a bounded next-record request. For an unseen resolver path, request targeted resolver records. End inconclusively if the links are missing. Lesson 4 will examine harmless encoded training content; encoding alone proves no tunnel.
