# Data dictionary

`dns-exchange-worksheet.csv` is a blank analyst template. One row denotes one decoded packet, with associated exchange decisions; use another row for a retry. `capture_id` identifies the preserved file; `packet_ref` is its actual decoded frame reference; `packet_time_utc` is the displayed timestamp converted only with documented clock settings; `collection_point` names the observed link. `src`, `dst` are packet IPs; `direction` is `request` or `response`; `dns_id`, `qname`, `qtype`, `answer_rdata` transcribe decoded DNS fields. `paired_ref` cites a counterpart, `ambiguous:3|4` for the reply to the retry group, or `unobserved`. A decoder association does not prove which request caused a response. `repeat_class` is `new`, `retry`, `label_repeat`, `response`, or `uncertain`. `variable_labels` identifies exactly the selected request text; `request_chars` counts its visible characters under the documented unique-label rule. `candidate_answer_string` and `answer_chars` record separately selected visible answer text and its character count. Use `NA` where no eligible text is measurable; `0` means eligible text was assessed but excluded by the stated rule. `host_event_id` cites a separate fictional scenario metadata record, not packet-derived attribution; `clock_offset_status` is `measured:<value and units>` or `unmeasured`. `notes` records inclusion rules, uncertainties, and alternate explanations. Never replace missing evidence with a guessed value.

`host-events.csv` contains **authored synthetic scenario metadata**, not endpoint telemetry produced by the builder. `event_id` is its reference; `host_id` and `host_ip` are fictional scenario identifiers; `record_time` and `time_zone` describe its recorded clock; `measured_offset_to_packet_clock` states whether an offset was actually measured; `event_type` and `detail` describe the fictional activity; `provenance` distinguishes it from packet evidence. A UTC-formatted timestamp does not establish clock synchronization or a process-to-DNS link.

`dns-timing-spec.json` uses the supplied synthetic version-1 builder schema: ordered `events` have timezone-qualified `timestamp`, DNS `kind`, documentation-network `src`/`dst`, UDP `sport`/`dport`, reserved `name`, and `transactionId`; `dns-answer` additionally has a documentation-network `answer` IPv4 address. Event order is a design index, **not** a verified capture frame number.
