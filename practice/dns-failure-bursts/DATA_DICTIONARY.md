# Data dictionary and evidence boundary

`transactions.csv` is **authored synthetic scenario design**, not packet-derived telemetry or an endpoint log. Each row specifies one intended query packet and, when `reply_ms` exists, one intended response packet. `row` is an author label, **not** a frame. `view` selects a separate supplied capture. `query_ms` and `reply_ms` are integer milliseconds after `collection-notes.json`'s `baseUtc`. `src,dst,sport` are query source/destination IPv4 addresses and UDP source port; query destination port is 53. Responses reverse endpoints and ports. `id` is a decimal 16-bit DNS transaction ID. Match using question name, type, class, ID, endpoints/ports, direction, and time—not ID alone.

`name` is a reserved `.test` question; `qtype` is A=1 or AAAA=28; `qclass` is IN=1. `rcode` describes an *intended visible reply*: NXDOMAIN=3 means name error; NOERROR=0 can accompany an A answer or zero requested answers. An empty `rcode` and `reply_ms` mean **no reply designed in that view**, not a DNS failure code. `answer_a` supplies an A record (TTL 60 seconds); empty on NODATA or NXDOMAIN. `soa_zone`, `soa_ttl_s`, and `soa_minimum_s` specify one SOA authority record, in seconds, when populated. The other SOA fields are in `fixture-spec.json`. Inspect NOERROR with zero answers and authority for this exercise's NODATA; NXDOMAIN is not interchangeable with it.

`collection-notes.json` supplies authored UTC scope and **scenario endpoint roles**, not identities established by packets. `fixture-spec.json` is the packet-design contract implemented by this kit's separate `generate.py`; it is not a version-1 generic-builder fixture. Author-only timed pairs in it are choreography, not packet-only proof that a particular client caused an upstream query. No application, search-list setting, cache hit, or malicious attribution is supplied.
