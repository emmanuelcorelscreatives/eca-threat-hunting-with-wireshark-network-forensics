# Answer Guide — Expected Reasoning

**Reasoning key, not packet findings.** Accept varied wording when all fields are complete, scope and confidence are explicit, and no observations are invented. Reject claims of user identity, execution, encrypted content, or no activity based on packet absence.

## Case checks

1. **External contact:** Ask why; appearance is not a verdict. Include scheduled activity, needed capture context, a packet-backed plan, and closure, escalation, or missing-evidence request.
2. **Overlapping sources:** Preserve original-source provenance and overlap limits. Name the transcript, timeline, and notes. Verify reproducibility before relying on the summary.
3. **Download:** Delivery evidence cannot prove execution. Use a timeline/register, separate network from host evidence, and request host evidence if execution matters.
4. **Internal sequence:** Compare compromise, service-account trouble, and maintenance. Account identity stays unresolved. Use a timeline/shortlist and seek host or identity records.
5. **Recurrence:** Compare command-and-control with ordinary software or an agent. Regular timing is insufficient. Assess timing, resolution, and context; state the response owner's unresolved question.
6. **Service sequence:** Observation points may differ. Compare movement with administration. The map/timeline/scope must separate supported links from systems requiring checks; host or identity evidence may help.
7. **Combined leads:** Support each stage independently, record the missing window and harmless lookalike, and never link by proximity alone. The report/timeline/appendix must expose gaps.
8. **Open investigation:** Questions and limits are learner-selected. Encrypted content or possible data loss may remain unresolved. Use only narrated portfolio artifacts matched to the intended decision.

> In every case, connect the starting hypothesis, capture scope packet evidence, alternative explanations, and the next useful action.
