# Data dictionary and provenance

Everything in the capture is authored offline from fixture-spec.json using build_fixture.py. It is real downloadable PCAPNG data decoded by actual TShark and viewed in actual native Linux Wireshark, not a capture of a production network. Documentation IP ranges and illustrative names are labels. The builder creates valid IPv4/TCP checksums and DNS/Hello bytes but no complete TLS session or incident evidence. UDP's IPv4 zero checksum is permitted. Packet times are UTC design values on one fictional link; no measured collector metadata, loss, offset or continuous coverage exists.

fixture-spec.json: epoch is Unix seconds; sessions list role, host, peer, client source port, start seconds relative to epoch, illustrative SNI name and absolute initial sequence numbers. Four sessions use destination TCP 443. Builder-authored DNS adds a third candidate answer without a subsequent connection. TLS records contain ClientHello and ServerHello only. Decoder JSON and CSV fields retain actual frame references; epoch seconds are distinct from local display time.

process-scenarios.csv: scenario selects one mutually exclusive hypothetical path. recordId identifies a card; recordKind is match, nearby-nonmatch or missing. host, eventTimeUtc, localIp/localPort, remoteIp/remotePort and processLabel describe a hypothetical host record. Empty fields mean unavailable. clockOffsetMs=150 means the assumed host clock leads packet UTC, so subtract 150 ms. coverageStartUtc/coverageEndUtc are scenario source windows on the packet UTC reference, not capture bounds or measured host coverage; coverageStatus states their limited scope. They do not establish retention or ownership in reality.

agent-baseline.csv: baselineId identifies a synthetic policy card. host and role set endpoint scope; approvedProcessLabel, approvedRemoteIp/Port and windowStartUtc/windowEndUtc constrain a conditional comparison. approvalStatus=scenario-approved is an assumption, not evidence a program ran. provenance explicitly names synthetic origin. Approval is separate from socket ownership and does not transfer between hosts.

verification.json contains actually executed independent framing/checksum/TShark checks, and exact capture hash. execution-proof.json records actual byte-identical rebuild, refusal to overwrite and bad-input rejection. Native screenshots have their own SHA and role-limited review; they prove only their visible Linux view. Their approval does not validate Windows, host telemetry, main video or rendering. Inventory lists the other package files and is included as an envelope; it intentionally omits its own recursive hash.
