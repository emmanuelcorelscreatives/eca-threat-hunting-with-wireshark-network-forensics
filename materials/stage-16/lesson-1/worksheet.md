2. Inspect the candidate within the fixed host and interval. Explain whether the repeated SYN is a separate session. Do not infer blocked traffic from missing replies.
3. Remove only the candidate condition. Record the exact remaining host/time filter and Conversations Limit to display filter setting. List address pairs separately from transport sessions. Identify the out-of-window control without carrying it into the bounded result.
4. Record DNS query/response frames, name, transaction, both actual A answers and the response time. Check which returned addresses the host contacted during this interval. State how multiple answers, caching and shared infrastructure limit the inference. Missing DNS in a separate case is a visibility gap, not proof of no resolution.
5. Record the visible HTTP Host, request/response frames, payload lengths and stream. Record what is absent on the candidate's port 443 flow. A port alone does not demonstrate TLS or reveal encrypted application content. After Follow, restore and record the bounded host/time filter.
6. Evaluate the near-time incidental peer. State the independent evidence required before adding it to a relationship diagram. Distinguish a packet-supported DNS/application correlation from process ownership, endpoint control or malicious purpose.
7. For each retained session write source capture, frames, timestamped relationship, support, competing ordinary explanation and missing evidence. Keep unsupported leads separate. Consider approved management software or shared infrastructure without inventing an agent baseline or process-network excerpt.
8. Apply the stop rule: carry only checkable packet-supported links into the next lesson's host-to-infrastructure timeline. Name the specific missing evidence needed to expand further. End with a bounded shortlist, not a command-and-control verdict.
