# Answer guide — reasoning key

No capture or previous report was inspected here. Case references, hashes, times, metadata, and results stay blank until checked. In a completed case, look for bounded authorization, original and working copy, documented coverage, reproducible time format and filter, the Conversations setting, distinct connection starts, and replies. Packet counts alone do not establish repeats or intent; absence beyond sensor coverage does not rule activity out.

**Synthetic A — potentially benign:** Confirm that a named ownership and schedule record matches observed traffic on the same asset within the review window. Without that check, choose unresolved rather than assuming a harmless cause.

**Synthetic B — escalation candidate:** If actual source, hash, frame, time, and stream references support separate starts and context checks leave them unexplained, request response-owner review. State the affected asset, limits, needed decision, and why sensitivity or evidence expiry warrants urgency. Do not call it confirmed compromise.

**Synthetic C — unresolved:** Request review-window assignment or translation records to answer which asset used the address. Ask the network evidence owner whether an already-existing, authorized, same-window opposite-view capture covers the missing direction; if replies are missing, request that return-path view to determine whether replies occurred outside this capture's view. If no suitable record covers that direction, leave the question unresolved. A familiar destination name cannot settle either question.

A usable playbook permits all three outcomes and ends with a documented explanation, a handoff, or an owned evidence question. No command execution or packet finding is claimed.
