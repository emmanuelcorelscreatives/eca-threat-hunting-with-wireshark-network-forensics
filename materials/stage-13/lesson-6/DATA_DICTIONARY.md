`ip.src` and `ip.dst` give packet direction; `tcp.srcport` and `tcp.dstport` scope the peer and distinguish source-port tuples. `tcp.flags` in `decoded-fields.stdout.csv` is the decoded bit field: `0x0002` is a SYN without ACK, `0x0012` a SYN-ACK, `0x0010` an ACK, and `0x0018` PSH-ACK in this fixture. `tcp.flags.syn` and `tcp.flags.ack` are decoded booleans. An ACK matching a prior observed reverse-sequence end within this file does not certify unseen traffic, collection health, or unknown earlier ACK coverage. `tcp.len` counts TCP payload bytes; `tcp.payload` renders those bytes in hex, not an identified application.

## Frame bytes are not payload bytes

`frame.len` is an entire Ethernet-frame length; `frame.cap_len` is the captured length. Conversation `Bytes` sum **frame bytes**, not TCP payload. The 59 captured frames total **3,208 packet bytes** (`capture-info.stdout.txt`; `protocol-hierarchy.stdout.txt`), while the physical PCAP occupies **4,176 bytes**, including a 24-byte global header and 59 × 16-byte record headers: **24 + 59 × 16 + 3,208 = 4,176**. `native-file-accounting.json` explains why the approved Linux 4.4.0 Capture File Properties image displays a **4,160-byte native Length** counter, 16 bytes below the physical size. It is a counter distinction, not evidence that the last record is truncated. The chooser's approximately 4.08 KiB listing and `capinfos` physical file size are different presentations again.

The hierarchy's **22 generic data frames / 1,210 bytes** are 22 whole frames of 55 bytes each (`all-frames.stdout.txt`). Each has `tcp.len=1`, so together they have **22 TCP payload bytes**, not 1,210 payload bytes or an extracted file. The synthetic letters `x`, `y`, `p`, and `q` appear as hex `78`, `79`, `70`, and `71`. They establish no request, response purpose, encryption, beacon, or command meaning. In `native-05-endpoints.png`, **Ethernet (4)**, not IPv4, is the selected unfiltered Endpoints tab; its 43, 43, 16, and 16 counts are endpoint participations, so they must not be substituted for IP-conversation counts.
