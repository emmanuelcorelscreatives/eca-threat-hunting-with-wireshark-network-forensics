# Setup and observed environment

Extract the complete ZIP into one directory. Keep its relative filenames and originals unchanged; work on a copy. The evidence was collected on Ubuntu 24.04, with native Wireshark/TShark 4.4.0. The saved narrator uses Windows 11; these are separate platform facts. Windows instructions below are a learner procedure, not a claim that these exact commands were executed there.

1. Install Wireshark 4.4.0 including TShark, and Python 3.10 or later. No paid account, remote server or special service is needed.
2. Run the local checker: `python3 verify_fixture.py --tshark /path/to/tshark`. On Windows use `py -3 verify_fixture.py --tshark "C:\Program Files\Wireshark\tshark.exe"`. The supplied `verify-fixture.ps1` wrapper calls the same Python checker; it does not bypass PowerShell policy or run service-control commands.
3. In Wireshark choose File → Open and open `rpc-service-synthetic.pcapng`. The capture uses dedicated loopback TCP port 17454, not the default SMB port. Select a TCP packet, choose Analyze → Decode As, set TCP port 17454 to NBSS (NetBIOS Session Service), and Apply. A successful decode shows SMB2 and SVCCTL rows. If not, verify the port and decode before treating an empty filter as evidence. The reproducible CLI equivalent is `tshark -r rpc-service-synthetic.pcapng -d tcp.port==17454,nbss -Y "smb2 or dcerpc"`.
4. Set View → Time Display Format to a date/time UTC option when recording absolute times, or use `decoded-fields.csv` epoch timestamps converted explicitly to UTC. Do not claim a screenshot's relative Time column is absolute UTC.
5. First inspect the lesson filter `smb2 or dcerpc`, then change it to `dcerpc` for the required Conversations comparison. Open Statistics → Conversations. Select TCP, compare Limit to display filter unchecked and checked, then close. Both states can retain one endpoint pair here; compare packet totals as well. Scroll the horizontal scrollbar right to see Rel Start and Duration; this native build retains underlying conversation timing even when filtered counts change. See the explicit model in answer-guide.md. The required comparison uses `dcerpc` throughout both checkbox states. Original frame references do not renumber.
6. Select the relevant frame and expand SMB2 and DCE/RPC / Service Control in Packet Details. Cross-check session, tree, pipe file handle, bound interface and call ID before interpreting any opnum. Compare replies and status, not just request names.

`execution.json`, all-frames.stdout.txt, rpc-verbose.stdout.txt, decoded-fields.csv and verifier-execution.json are actual read-only tool output. Native PNGs and native-validation.md document only their visible Linux GUI states. This package includes both loopback directions but stops before connection close; it is not a complete network monitoring window. Encrypted SMB, other hosts and RPC over TCP are outside this demonstration.
