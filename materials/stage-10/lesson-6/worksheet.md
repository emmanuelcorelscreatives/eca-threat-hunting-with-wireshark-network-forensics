# HTTPS visibility worksheet

Work from the supplied files first. Record answers before reading `answers.md`.

1. Identify the source filename, SHA256, capture point, host mapping and server-port direction. Record first/last observed packet UTC/epoch times, the simulated report anchor and clock limitations. What evidence is unavailable? Do not substitute the original unsupplied case.
2. Use each anchor through anchor + 1 second as the equivalent comparison window. Translate the UTC anchor from fixture.json to epoch if needed using Python `datetime.fromisoformat(...).timestamp()`. All supplied packet times should be checked against it. Use a filter of the form `frame.time_epoch >= START && frame.time_epoch <= END && tcp.port == PORT`, replacing START/END/PORT with your own inspected values. Record the literal filter. The observed burst lengths can differ within these equal windows.
3. Apply `tls`, then `tls.handshake.type == 1`, then `tls.handshake.extensions_server_name`, keeping the scope explicit. Select a matching packet and expand TLS → Handshake → Extensions → server_name. Record actual frame, time and visible name. If recognition fails, follow setup's Decode As instructions. What would an empty result mean? Why is SNI not a URL path? Explain missing-handshake and ECH limits without claiming this capture contains ECH.
4. With the scoped `tls` view applied, open Statistics → Conversations → TCP. Record whether Limit to display filter is on. Record included endpoint ports, start time, duration, frame counts and both byte directions. Toggle the checkbox off and record the broader whole-capture totals separately. Repeat with `tls.handshake.type == 1` as a deliberately narrower scope to show why totals can change. Never compare differently scoped values as equivalent.
5. Select a TLS packet and follow its TCP stream. Confirm the endpoint ports. Without keys, identify what remains unreadable. Restore your scoped filter afterward. Does this expose HTTP method/path, redirects, response body, filename, hash, saved-object identity or execution? Do not export encrypted bytes as an identified HTTP object.
6. Repeat for the known benign updater in its equivalent anchor-relative window. Compare direction, traffic volume and timing. Explain why similarity does not prove benignness and difference does not prove malice. Give one ordinary response/updater explanation for server-heavy traffic.
7. Compare visible HTTP and undecrypted HTTPS: which permits examining methods, status codes, paths, redirects and captured object content; which instead supports endpoints, timing, direction and visible handshake information? Do not require an earlier capture.
8. Read the mock endpoint excerpt. Align host/time and identify the artifact. Does the process event link to it? Distinguish unconfirmed execution from proven non-execution. Request appropriate real browser/download/proxy/endpoint records and host/clock mapping.
9. Write separate sentences: observed metadata (with actual frames/filter/scope); delivery hypothesis; updater alternative; bounded conclusion; next evidence request. Use inconclusive when hidden content or missing linkage blocks stronger claims.

Independent transfer task: repeat on a separate authorized capture with supplied host mapping and coverage. Do not collect third-party data. Record no frame references until inspecting that file. If none is available, submit the completed provided-file exercise and list required evidence; do not claim to have completed your own capture.
