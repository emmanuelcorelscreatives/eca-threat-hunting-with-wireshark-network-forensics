# Source, clocks and fields

`captures/fixture.json` is collection/application provenance. `synthetic` labels the scripted scenario. `host_id` names the single lab host. `capture_point` is Linux lo. `mapping` identifies both endpoints as 127.0.0.1 and requires TCP-port roles. `clock` explains that application and tcpdump timestamps use the same host clock, without independent clock-offset measurement. `known_gaps` lists excluded external networks, DNS, ECH, browser and endpoint telemetry.

Each scenario has `role`, capture `file`, server `port`, visible `sni`, a `simulated_report_anchor_utc`, collection finish time, and application `receipt`. The anchor is an authored exercise event, not a real user report. Receipt request/response byte counts come from application code; they are not PCAP deductions, a saved-file size, or a packet-derived object identity. `negotiated_tls` is an application observation independently checked against TLS handshake fields. The updater designation comes from controlled generation.

`verified-results.json` is executed TShark evidence. SHA256 and bytes bind each capture; frames count actual decoded packets. `first_epoch` and `last_epoch` bound observed packet timestamps, not proof of the collector's entire uptime. Duration is last minus first. `client_hello_frame` and epoch are measured. `encrypted_record_frames` identifies outer content type 23, including TLS 1.3 opaque records; their hidden inner content cannot be inferred from that label. `frame_length_totals_whole_capture` sums full recorded frame lengths, including network headers and handshake traffic. It is neither unique TCP payload nor object size. PCAP file length includes global/packet headers and is a different quantity. Full raw CSV and CLI conversation output are retained.

`captures/endpoint.jsonl` contains two authored mock records on the same host/time basis: artifact `mock-artifact-A` and process creation `ordinary-helper` with null `linked_artifact_id`. The timestamp permits alignment; absence of the link does not prove non-execution. No mock artifact hash or filename is derived from packets. The excerpt is incomplete by design.

`commands-and-evidence.json` records executed filter, conversation-scope and raw follow checks with exit codes/stdout/stderr. `checker-rejection-proof.json` records deliberate invalid-copy rejection. `current-kit-inventory.json` binds every other delivered file by SHA256 and length; its own hash belongs to the publication receipt to avoid recursive self-hashing.
