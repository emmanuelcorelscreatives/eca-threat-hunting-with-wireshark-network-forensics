# Fixture and manifest dictionary

The three JSON files use the supplied offline builder's synthetic version-1 schema. Each ordered `events` record has an explicit UTC `timestamp`, `kind`, documentation-network IPv4 `src`/`dst`, and kind-specific fields. DNS records carry reserved `.test` names, ports, transaction IDs, and answer addresses. TCP records carry ports, flags, sequence and acknowledgment numbers, and optional harmless text. Other UDP records carry ports and harmless text. No event represents a real collector, user, or application verdict. Source A is supplied as `source-a.json`; the optional rebuild writes `rebuild/source-a.pcap` before conversion. The shipped original and working PCAPNG files are already built.

`case-manifest.csv` is the preserved historical blank intake template; `verified-intake.csv` is its completed measured counterpart for the shipped paths. Their columns: `source_id` identifies one case file; `original_path` is its generated, retained training original; `working_copy_path` is the only analyzed copy; `capture_point`, `capture_window_start_utc`, `capture_window_end_utc`, and `collection_limits` are authored **scenario metadata**, not packet-derived coverage measurements; `original_sha256` is established at intake; `working_sha256` identifies analyzed bytes; `profile` and `filter` state comparison settings. Empty hash fields must be filled from actual files, never guessed. The initial `none` filter describes unfiltered tables; record the scoped expression separately with scoped results.

Addresses are reserved documentation addresses. `192.0.2.10` is the synthetic question endpoint; `192.0.2.53` is its synthetic DNS peer; `198.51.100.20` is its TCP peer. The `.77` and `.88` pairs provide other UDP relationships. Point labels P1/P2 and declared windows are exercise assumptions; missing or unreliable coverage in an actual authorized case must instead be marked unknown.
