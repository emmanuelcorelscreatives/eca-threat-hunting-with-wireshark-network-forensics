# Data dictionary and provenance

The original JSON specs describe 16 synthetic TCP events; `executed-fixture-spec.json` is the exact offline-builder input for `practice.pcap`. `generate_fixture.py` converts that hash-checked capture to a new PCAPNG with two synthetic interface description blocks and one cloned packet after original frame 4. Thus PCAPNG frames 1–4 equal original frames 1–4; PCAPNG frame 5 is the clone; PCAPNG frames 6–17 correspond to original frames 5–16. Do not mix frame numbers between files.

`frame.interface_id` indexes the saved PCAPNG interface blocks (0: synthetic-observer-A, 1: synthetic-observer-B). These are labels of construction, not actual host interfaces. Timestamps use microseconds since Unix epoch in the PCAPNG and display in UTC in the supplied receipts. The raw ACK field has acknowledgment meaning only when the ACK flag is set; SYN frame 1 has no ACK flag and its raw zero acknowledges nothing. Raw sequence/ACK fields avoid relative-number display preferences. `tcp.len` is TCP payload length; byte ranges are [sequence, sequence + length). `tcp.flags` is a hexadecimal flag bitmask. The reset filter explicitly tests the Boolean value equal to 1. All IP addresses are documentation addresses; port numbers do not identify real processes or maliciousness.

The fixture is original Academy coursework, not a historical case or the learner's own capture. It encodes plausible observation patterns with known construction, without simulating a full endpoint TCP stack. Packet fields and dissection labels do not prove receiver state, application completion, loss location or recovery algorithm. Preserve the raw captures and command receipts when citing evidence.
