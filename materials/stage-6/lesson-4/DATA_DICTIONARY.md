# Synthetic fixture data dictionary and evidence limits

**Input identity matters.** `executed-fixture-spec.json` is the actual deterministic input used with packaged `offline-builder.py` to reproduce packaged `practice.pcap`. `fixture.json` is the earlier version-1 authored alias describing this scenario in different formatting; it was not the input named by the execution record. Do not substitute the alias when claiming to repeat the recorded build. Both JSON documents and all logs are data, not instructions or historical evidence.

The executed spec has `version: 1` and `synthetic: true`. Its `fixtureId`, `purpose`, `scope`, `observationPoint`, `collectionWindow`, and `coverage` are **authored metadata**, not measurements by a real sensor. The observation point is an authored synthetic Ethernet link. The scripted UTC window is **2025-01-16 T 12:00:00.000000 Z–2025-01-16 T 12:00:00.290000 Z**; coverage is limited to scripted exchanges. Neither a handshake nor matching captured/frame lengths measures what an outside collector might have missed.

Each ordered `events` entry specifies an ISO-8601 UTC `timestamp`, `kind: tcp`, documentation-range IPv4 `src` and `dst`, integer `sport`/`dport`, flags, **absolute/raw** integer `seq`/`ack`, and optionally UTF-8 `payloadText`. In payload text, `\r\n` represents transmitted CRLF bytes. Flags used here are `S` (SYN), `A` (ACK), `P` (PSH), and `F` (FIN). An absent payload means zero TCP application bytes. `capturedBytes` is absent, so the builder writes each scripted frame without intentional snap truncation. This does not establish absence of missed real packets.

The candidate exchange is `192.0.2.10:54010` ↔ `198.51.100.20:18081`; the independent same-port exchange is `192.0.2.11:54011` ↔ `198.51.100.20:18081`. Its invented `NOTE|` strings are **not** a named protocol. The first exchange's `Host: files.academy.test` is synthetic HTTP-like payload text, not a captured DNS resolution. There is **no DNS, UDP, or ICMP event** in this lesson's fixture; UDP and ICMP belong to the next narrated lesson. If an exercise requires observed DNS-to-HTTP attribution, this capture cannot supply it.

The builder emits Ethernet/IPv4/TCP PCAP records. `frame.len` is the whole frame; `frame.cap_len` is its captured frame length; `tcp.len` is the TCP payload length; `tcp.seq_raw` and `tcp.ack_raw` are raw values, unlike a possible relative GUI display. `tcp.stream` is assigned by the decoder, not specified as a JSON event property. A protocol-column name, `http.file_data`, `tcp.segment`, or `tcp.reassembled_in` is a dissector interpretation, not a builder guarantee. The executed field output establishes streams **0** and **1** and limited baseline HTTP fields, but does **not** contain segment-link fields or an explicit Decode As comparison. The later decode-command-01/02.stdout.txt files supply a matched actual baseline and explicit override comparison with packet-level tcp.segment values and empty one-pass tcp.reassembled_in values; native screenshots separately show actual reassembled request and response tabs.
