# Synthetic data dictionary

Both version-1 JSON specifications have `synthetic: true`, a `fixtureId`, and timestamp-ordered `events`. Each event has a UTC `timestamp`, `kind`, documentation-only `src`/`dst`, and, for TCP or UDP, integer `sport`/`dport`. TCP events also specify `flags`, byte-oriented `seq`/`ack`, and optional UTF-8 `payloadText`; UDP may carry `payloadText`. The builder creates Ethernet/IPv4 frames. An event is an authored input, **not** an observed frame number.

`context.json` contains `captures` (`id`, output `filename`, input `spec`, `intendedWindowUtc`, `capturePoint`, `coverage`), `assets` (`asset_id`, `ip`, `role`, `sensitivity`, `owner_status`, `schedule_utc`, `record_id`), `peers` (`ip`, `label`, `owner_status`), `jobs` (record, asset, peer, dated UTC approval window, confirmation), `deviceRecords` (record, asset, peer, UTC effective time, configuration description), and `telemetry` (lead ID, available comparison, missing information). Record IDs identify **scenario metadata**, never packet evidence. An IP identifies a fixture endpoint, not a person, application, or process. `unknown` means not established; `missing telemetry` means a relevant record is unavailable, not that a claim is true or false.

`decision-log-template.csv` contains `priority`, `lead_id`, `testable_hypothesis`, `source_capture`, `observation_window_utc`, `capture_point_and_gaps`, `view_or_filter`, `statistics_scope`, `actual_frame_references`, `packet_observation`, `inference`, `role_matched_baseline_and_coverage`, `inventory_sensitivity_source`, `schedule_check`, `supporting_or_conflicting_record_ids`, `missing_telemetry`, `alternative_explanation`, `decision_reason`, `next_test`, and `reopen_condition`. Fill empty cells with findings or an explicit unknown; never substitute a specification event's position for an actual frame reference.
