# Actual verification and evidence limits

`actual-execution.json` identifies actual Ubuntu 24.04.5 LTS command executions. Native TShark and Wireshark are version 4.4.0; `current-version.stdout.txt` records the binary version. The packet generator is local, deterministic and offline. `generate_fixture.py` was actually executed into a fresh temporary path, produced byte-identical learner pcapng, and refused to replace that output. `current-regeneration.*` and `current-existing-output-refusal.*` preserve those results.

`current-fields.stdout.txt` was decoded from the exact delivered unannotated pcapng with IP, UDP and TCP checksum validation enabled. Checksum status 1 means good; absent transport fields are not errors for other protocols. All applicable checksums are good. Six frames have matching captured and reported lengths. Actual `_ws.malformed` and truncation filters produce no rows. These facts do not make this a historical collection or prove traffic outside the six-frame file. The checksum and dissection facts are author measurements; the learner verifier also pins the exact bytes containing those checked fields.

The `current-filter-*` logs contain actual frame references for each named filter. `current-commented`, `current-displayed` and `current-captured` log saved comments and frame counts for the actual native GUI outputs. Original input remains unannotated and unchanged. `verify_fixture.py` was actually run successfully against all five pinned captures. Four temporary corrupted copies were rejected: unannotated input, commented output, displayed output and capture manifest. None of those negative tests modified the real inputs.

`native-24-dns-pale-rule.png` and `native-25-pale-dns-rows.png` show the actual DNS rule and row colors. `native-26-session-marks.png` shows two current marks. `native-07-comment-checked-fields.png` records the full proposed synthetic observation in the author comment dialog. `native-13-reopened-existing-comment.png` shows the persisted comment after Save As and reopen. `native-17-export-default-displayed.png` shows Displayed selected by default with DNS active, and `native-18-export-captured-six.png` shows Captured selected with six packets. `native-19-bookmarked-filter-persisted.png` shows the saved `dns` filter under its default name. The actual profile files are delivered as text for inspection, not automatically installed.

The source PCAP, old `all-frames`, `capture-info`, `ip-conversations`, `tcp-conversations`, `protocol-hierarchy` and `malformed` logs are historical measurements of the original synthetic PCAP. They are not logs of the new pcapng and their filesystem sizes differ. Current logs are prefixed `current-`; use the current capture hashes. Packet-byte totals, pcap file size and pcapng file size are different units. The source PCAP is 529 bytes, the unannotated pcapng is 656 bytes, and packet lengths sum to 409 bytes.

No original case capture, real host identity, live collection, Windows execution or learner-owned exercise completion is asserted. The narrated Windows 11 commands remain learner instructions. The actual host receipt describes Linux; native screenshots never establish Windows-specific behavior.
