# Data dictionary — labelled synthetic coursework

**Scope and provenance.** `practice.pcap` is a packaged, 1,883-byte synthetic Ethernet/IPv4 **classic PCAP**, not the unsupplied narrated-case capture or evidence of a real incident. Its SHA-256 is `fe798aee93a40286eebc18e3d683830b695b63b6618a886fe2c7fdb190cdcb15` (`capture-info.stdout.txt`: `SHA256`). Preserve that original and analyze a separately identified working copy. The assembled files have **not yet been versioned or published** as a student download.

**Specification and builder.** `executed-fixture-spec.json` is the **actual deterministic input** to packaged `offline-builder.py`. `fixture-spec.json` is a current byte-identical alias (both SHA-256 `762907fdaa3cbf4a00af603c4649d3cb87124a53135df8fef5cf32ef75b95000`), not independent proof that future aliases will match. The JSON requires `version: 1` and `synthetic: true`; ordered `events` supply timezone-qualified UTC `timestamp`, `kind`, documentation-only IPv4 `src`/`dst`, and kind-specific values. DNS events use ports, reserved `.example`/`.test` names, `transactionId`, and answer addresses where appropriate. TCP events include ports, **absolute** `seq`/`ack`, flags, and optional UTF-8 `payloadText`. The packaged Python standard-library builder constructs packets and checksums, writes microsecond-timestamped PCAP, sends no traffic, and **refuses** an existing output path. A recorded deterministic rebuild was byte-identical; the supplied TShark field export is not an independent checksum test. The older underscored builder name, Scapy generator, and PCAPNG naming were draft proposals, not this executable fixture.

**Authored scenario context.** In `asset-list.csv`, `asset_id` and `role` are fictional labels; `ipv4` is a documentation address; `valid_from_utc` is inclusive and `valid_until_utc` exclusive; `provenance` distinguishes authored mappings from packet observations. WKS-17’s address mapping covers this fixture’s packet window. Names and ownership of external peers are **not verified** by a DNS answer, Host header, or scenario label. `scheduled-activity-note.md` is an authored **UTC** business expectation: its 12:00–12:05 window and one listed destination are claims to test, not telemetry, proof of execution, or an exhaustive allowlist. It contains no process-to-connection record.

**Recorded decoder artifacts.** The `*.stdout.txt` logs named `capture-info`, `all-frames`, `ip-conversations`, `tcp-conversations`, `protocol-hierarchy`, and `malformed` record read-only analyses using pinned Linux TShark/capinfos 4.4.0; corresponding `*.stderr.txt` files retain stderr, including TShark’s root-user warning. `capture-info.stdout.txt` reports 22 packets, earliest/latest packet times, classic-PCAP file and data sizes, microsecond precision, Ethernet encapsulation, and a single file interface. A PCAP file-interface entry is **not** a measured collection-point description or proof of complete paths. Empty `malformed.stdout.txt` means the executed `_ws.malformed` filter reported none, not that every checksum or possible capture defect was checked.

`all-frames.stdout.txt` is a **tab-separated, header-labelled field export**. `frame.number` is a reference in this file, not an identity across modified captures. `frame.time_utc` is a human-readable UTC string (`Jan 16, 2025 ... UTC`); `frame.time_epoch` is numeric Unix seconds. The pinned inventory does not support `frame.time_iso8601`; no output from that field is claimed. `frame.len` and `frame.cap_len` are recorded frame and captured-frame lengths; `tcp.len` counts TCP payload bytes, including application headers where present. `tcp.seq_raw`/`tcp.ack_raw` are absolute wire-field numbers; Wireshark can display **relative** sequence values instead. `dns.qry.name`/`dns.a`, `http.request.method`/`http.request.uri`/`http.host`, `http.response.code`, and hex `http.file_data` are decoded packet fields, **not** verified service ownership or software identity. In frames 7 and 18, `http.file_data=4f4b` represents the two visible body bytes `OK`, not an update file. Conversation `Bytes` are **recorded frame-byte totals**, not application-body or PCAP-file byte totals.

**Limits.** The file contains decoded DNS and HTTP over UDP/TCP, not endpoint-process evidence, independently measured clock accuracy, traffic beyond its first/last packets, a verified observation point, or PCAPNG collection metadata. It does not supply other protocols merely because an investigation might need them. The bounded Linux GUI views are now checked in `native-validation.md`; Windows results remain untested. If the narrated case or a richer protocol, collection-metadata, or process-attribution requirement depends on missing data, obtain the authorized materials; do not manufacture findings from this fixture.
