# Data dictionary and scope

`packet_plan.csv` is generator input; decoded evidence is separate. Row order maps A1–F2 to frames1–14 only after the supplied generator/checker execution. `case_id` groups A–F, `step_id` names a step, and `offset_ms` is milliseconds after `baseUTC` in `capture_metadata.json`. `src_ip`/`dst_ip` use documentation networks; ports apply to TCP; `tcp_flags` uses S=SYN, A=ACK, R=RST. `seq`/`ack` are raw header numbers, not application progress. ICMP-only type, code and quoted-step fields are blank for TCP; TCP-only fields are blank for ICMP.

The standard-library generator uses locally administered synthetic Ethernet MACs `02:00:` followed by the four IPv4 address bytes, EtherType0800, IPv4 TTL64 and no IP options. It computes IPv4/TCP/ICMP checksums. It encodes no payload, no live interface and no actual device identity. E2/F2 quote the original IPv4 header and first eight TCP bytes of E1/F1. Those bytes include ports/sequence but not TCP flags. IPv4 type3 codes include0=network,1=host,3=port,13=communication administratively prohibited; read each actual sender/code rather than inferring intent. No ICMPv6 result is supplied.

`capture_metadata.json` describes an authored emulated client-facing point and declared seven-second scenario window, not measured capture coverage. Verification proves encoded packet observations only. The first/last packet bounds differ from the declared scenario bounds. Tool stdout/stderr and `execution-receipts.json` preserve actual local commands, independent byte validation, deterministic rebuild and scratch rejection tests. `native-gui-execution.json` binds actual Linux filter screenshots to this capture; it does not establish expanded quotation GUI proof, Windows execution, or video approval. Source PCAP bytes were preserved during GUI collection.
