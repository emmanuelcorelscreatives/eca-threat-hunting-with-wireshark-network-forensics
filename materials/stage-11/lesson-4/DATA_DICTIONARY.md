# Data dictionary and provenance

fixture-spec.json is executable input data for build.py version 1: every event specifies UTC timestamp, protocol kind, numeric source/destination, ports, queried name, transactionId and, for answers, returned address. NBNS events additionally give suffix 32 (hex 20); broadcast=true controls the query flag and Ethernet destination. TCP events give raw sequence/acknowledgment values and flags. The assumed client subnet is 192.0.2.0/24, making 192.0.2.255 its broadcast destination. LLMNR uses 224.0.0.252 and multicast Ethernet 01:00:5e:00:00:fc. These are generated packets, not measured hosts.

asset-map.csv is a scenario assumption: ip is the numeric asset; role and owned_names explain expected ownership; authorized_responder_for states approved service in the scenario; client_dns and client_nbns give the client's assumed configuration; contact_note gives a fictional lab contact role. Empty values are unknown or not applicable, not confirmed absence. An answer source can differ from the returned address.

paper-examples.csv preserves older hypothetical L1/N1/N2 discussion rows. Its timestamps and IDs are paper data, not frame references or an input to this PCAP. N1's broadcast interpretation uses the same assumed /24. Do not join the rows to packets solely by a similar name; use the capture-specific worksheet/key for actual frames.

fields.stdout.txt is an actual decoded CSV despite its .txt extension. It quotes fields, includes a header, and can have empty protocol-specific cells. The standard output and error files record historical read-only runs. execution.json binds those outputs to actual command arguments. raw-check.json independently parses the binary without importing build.py or TShark; raw-check-negative-tests.json records four actual rejected corrupt scratch inputs. Neither checker nor successful decoding establishes real host behavior or scenario inventory accuracy.

The generated 17-frame input supersedes an older unexecuted DNS-only draft. Published filenames are relative to this kit. build.py and fixture-spec.json are the canonical implemented equivalents of previous draft paths; practice.pcap is the sole canonical full capture. Native images document narrowly scoped application filter/list states, with source hash and independent review in native-independent-approvals.json when present. They do not assert hidden expanded fields or Windows execution.
