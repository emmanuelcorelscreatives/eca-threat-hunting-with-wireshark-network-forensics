# Install and verify the analysis tools

**Question:** Can this workstation open an authorized saved capture, and—separately—can this ordinary user start capture on an approved isolated interface? The scope is this OS, installation, user context, file, and adapter; neither result establishes another workstation’s capability.

1. Record your actual OS and installation method. For the Windows 11 demonstration, use Settings → System → About to record edition, version, and OS build. If Wireshark is missing, obtain the appropriate Windows installer from `wireshark.org/download.html`; otherwise keep last lesson’s installation. Record the installer’s Wireshark and TShark component choices and whether Npcap was offered and selected. An installer choice alone does not establish working capture. On macOS or Linux, record the exact system and its installation and permission observations instead; do not import a Windows driver conclusion.
2. As your ordinary user, open installed Wireshark and About Wireshark. Record its actual version and relevant build details, or its launch error. On Windows only, in PowerShell, go to **this installation’s** tools directory. Run separately: `.\tshark.exe --version`, `.\capinfos.exe --version`, `.\editcap.exe --version`, `.\mergecap.exe --version`, and `.\dumpcap.exe --version`. Preserve each exact response or error in the record and your local command transcript. If an executable is not found, check that directory and the selected components; that error does not establish a capture-permission failure.
3. In Wireshark, open Capture → Options → Input. Record the interface names. Compare an intended lab adapter with your approved isolated lab’s adapter information before selection. If the view is unclear, run `.\dumpcap.exe -D` from the same tools directory and record its output or error. Discovery and activity indicators do not grant capture permission. If no approved adapter can be identified, stop the live check as unverified.
4. For **offline access**, choose File → Open and select an authorized saved capture, or the optional synthetic capture only after it exists and has been checked. Record its filename and whether Wireshark displayed it, or the exact error. With no file, record pending. Do not investigate its packets here or infer live access from opening it.
5. For **live access**, only if an approved isolated adapter is identified, use Wireshark’s capture control as an ordinary user for a brief start-and-stop permission check. Do not collect production traffic, generate traffic, set collection filters, or elevate the entire analyzer by default. Record whether capture started, any prompt or exact error, and whether packets appeared. A started but empty capture can still establish access for that test; an error does not establish its cause. Record Npcap status, restricted-access observations, and interface-list differences as next checks, not presumed explanations.

Keep the two outcomes separate. Leave unsupported findings blank, state alternative explanations and confidence limits, and identify the next useful check. The next lesson creates a repeatable Wireshark profile.

## macOS and Linux path

Use your system installation method and exact installed executable locations. From a terminal, separately run `tshark --version`, `capinfos --version`, `editcap --version`, `mergecap --version`, and `dumpcap --version`. If a tool is not on PATH, use its actual installed path; preserve the exact error. Run `dumpcap -D` only for the conditional interface-list check. These commands do not capture packets. Record actual OS details using your system About view or `/etc/os-release` on Linux, and identify your ordinary user context. Keep offline opening, interface discovery and permission conclusions separate. Do not import Npcap conclusions or change permissions without evidence.
