# Checkable answer guide

These are **decision rules**, not executed test results. Compare the worksheet with the learner’s saved observations.

- A displayed authorized file supports **offline pass for that file** only. An actual open error supports offline fail with its wording preserved. No available file means pending, not fail.
- A capture that starts on the identified approved adapter supports **live pass for that user, adapter, and test** even if no packets appeared. A recorded start error supports live fail for that attempt, not a confirmed driver or permission cause. No safely identifiable approved adapter means live unverified.
- A tool version response establishes that tool ran, not interface access. An executable-not-found error calls for checking the actual tools directory and selected components. An empty Wireshark interface view alone does not identify the cause; compare with `dumpcap -D` when possible.
- The decision-practice answers are: offline pass/live unverified; live access demonstrated for the brief test but traffic visibility unproven; and check the path and TShark selection before drawing any capture-permission conclusion.
