# Synthetic specification dictionary

All three JSON files use the supplied offline builder's synthetic version-1 event schema. Top-level `fixtureId`, `purpose`, `scope`, and `observationPoint` are **authored scenario metadata**, not packet-derived facts or measured collector properties. `events` are timestamp-ordered fictional Ethernet/IPv4/TCP records; `timestamp` is an explicit UTC instant. `src`, `dst`, `sport`, and `dport` identify endpoints; `flags`, `seq`, and `ack` define TCP control and byte positions; `payloadText` supplies fictional UTF-8 bytes. `capturedBytes`, when present, limits bytes saved from that generated Ethernet frame while retaining its original length.

Shared identifiers: A = `192.0.2.10:40000`; B = `198.51.100.20:8080`. Both addresses are documentation-only. Request text is `QUERY:STATUS` followed by a newline; reply text is `STATUS:OK` followed by a newline. The truncated specification limits the reply record to 54 saved bytes, leaving its application text unsaved. This models saved-byte loss **per record**, not a verified collector snapshot-length setting. The builder's classic-PCAP header uses a larger global snaplen and supplies no interface-drop or capture-point measurement. The one-sided specification omits B→A records; omission is authored visibility, not proof of why a real sensor missed traffic.
