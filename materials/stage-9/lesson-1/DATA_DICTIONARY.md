# Data dictionary

`dns-transaction-worksheet.csv` is an unchanged, header-only **33-column** worksheet. Add one row per proposed DNS query/reply pair; keep packet findings, authored scenario context and hypotheses distinguishable. `source_file`, `collection_point`, `window_utc`, and `visibility_limits` establish provenance and scope. For this fixture cite the actual `practice.pcap` or documented working-copy path and qualify the two link labels as **authored synthetic metadata**, not packet-derived interface observations. For another capture, use its own collection notes. A filtered-out or uncaptured packet is not evidence that no lookup occurred.

`query_frame`, `query_time_utc`, `transport`, `query_src`, `query_sport`, `query_dst`, `query_dport`, `query_flag`, `query_id`, `question_name`, `question_type`, and `question_class` describe the inspected question. `response_frame`, `response_time_utc`, `response_src`, `response_sport`, `response_dst`, `response_dport`, `response_flag`, `response_id`, `response_question`, `response_code`, and `answer_records` describe the checked reply. Record actual frame numbers and UTC times, not event-list positions presented as independently inspected results. The supplied export uses `frame.time_utc` for a readable UTC display and `frame.time_epoch` for seconds since the epoch; convert and label the format if entering an ISO-style UTC timestamp. `frame.time_iso8601` is unsupported in the pinned 4.4 build. Record DNS IDs consistently, stating decimal or hexadecimal where ambiguity is possible. Use `query`/`response` for flags only after checking them.

Format `response_question` as `name|type|class` and each verified **Answer-section** record as `name|type|value`, with semicolons between records. The response question’s `dns.qry.name` is not necessarily an Answer owner. A `dns.a` export by itself supplies an IPv4 value but does not identify its section, owner or TTL; inspect **Answers**, not Authority or Additional, before treating it as an answer record. Record a CNAME as an alias, not as an IP address. A requested A or AAAA type can differ from returned record types, and a response or NOERROR code alone does not guarantee a usable address. The builder’s DNS events encode two modeled A/IN question/reply exchanges, each with one successful response containing one A/IN Answer record with TTL 60; the packaged `offline-builder.py` source specifies these bytes, while the original all-frames field selection does **not** independently display class, response code, Answer owner or TTL. The newer actual `decoded-fields.stdout.csv`, `dns-details.stdout.txt` and native expanded-DNS views now supply those checked observations, as recorded in `native-validation.md`. The fixture does not contain AAAA, CNAME, a negative or empty Answer, or an incomplete pair.

`observed_requester` identifies only the requester supported on the stated link. `original_endpoint_status` distinguishes a verified client-facing endpoint from an original endpoint **unknown from an upstream-only view**. `hypothesis`, `alternatives`, `confidence`, and `next_action` keep assessment separate from packet observations. Use `not_visible` for fields of a packet outside the capture’s coverage, `none` for an inspected response containing no Answer records, and `unknown` for unestablished attribution. Do not use these tokens interchangeably or fill an absent response from the fixture design.

`executed-fixture-spec.json` is the packaged input to the attested deterministic build. Its timestamp-ordered `events` carry `kind`, documentation IPv4 `src`/`dst`, UDP `sport`/`dport`, reserved `.test` `name`, and integer `transactionId`; `dns-answer` also carries `answer`. `dns-fixture-spec.json` is the earlier authored alias with the same modeled events but different bytes and was **not** the attested input. Top-level scope and observation-point text is authored scenario context. The current builder refuses an existing output path: rebuild only in a fresh directory. The DNS event encoding does not supply collection interfaces, cache activity, AAAA, CNAME, or failure cases, even though the general builder also supports other event kinds.

Byte and sequence-number guardrail for **other** captures: this fixture has no TCP conversation (`tcp-conversations.stdout.txt` is empty, and the supplied all-frame `tcp.*` and `http.*` columns are blank). `tcp.seq_raw` would be an on-wire sequence number, whereas Wireshark can display a relative sequence number; do not conflate them. `frame.len` and Capinfos packet-data bytes include network headers; `tcp.len` is TCP segment payload bytes, not an extracted file’s size or content. Neither four DNS frames nor their 428-byte PCAP file size describe an application file.
