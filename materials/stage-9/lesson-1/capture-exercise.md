# Checkable questions

Use the assembled synthetic `practice.pcap` with `collection-notes.md`; enter **separate** CSV rows for the client-facing and upstream pairs after inspecting the packets. Cite the actual source and frames. A supplied command-output field, a builder prediction, and a GUI-inspected Answer are different levels of evidence; label them accordingly.

1. Locate each visible question and its candidate reply. What are their UTC frame times, IP addresses and transport? Verify query/response flags, reversed source/destination ports, matching ID and Question name/type/class. Does Wireshark offer a response-frame link, and does independent matching support it? Do not match on ID alone.
2. What is each reply’s response code? In **Answers**, what are the owner name, type and value of **each** record? Distinguish those records from the repeated Question, Authority, Additional, and the `dns.a` value in a broad field export. If there is no usable address, state that rather than inventing one.
3. Who is the requester visible on each *modeled* link? If the upstream pair alone were available, which original endpoint could its packets identify? Which part of your link description comes from authored collection notes rather than a per-packet interface identifier?
4. Do the shared name and close times prove this client caused the upstream query? What contemporaneous resolver client-request record or additional capture would test that hypothesis? Could the fixture establish a user or application?
5. If an actual client-facing pair appeared with no upstream packets, how would you test cache reuse against missed upstream coverage? Does this four-frame capture itself demonstrate either a cache hit or missing direction?
6. Could an address in an Answer prove a later connection? Could Wireshark’s displayed IP-associated name come from its own name-resolution information rather than the inspected DNS Answer? What packet evidence would each stronger assertion require?
7. Explain how you would record an AAAA answer, a CNAME alias, or a response with no usable Answer **if present in an authorized capture**. Identify which of these cannot be demonstrated with this A-only fixture; do not invent an extra fixture frame. Keep negative and repeated-lookup analysis for its appropriate evidence and the next lesson.
8. Perform the lecture’s separate exercise with one transaction from **your own authorized offline capture and its real collection notes**. Grade the matching method, section-level record transcription and honest attribution limits, not agreement with this synthetic fixture’s addresses. If the transaction is incomplete or requester remains uncertain, record the limit and next evidence needed.
