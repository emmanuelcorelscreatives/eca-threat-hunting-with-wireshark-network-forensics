# Fixture schema and evidence limits

fixture-plan.json version2 requires synthetic=true and exactly three captures, each with an observationPoint and chronologically ordered events. Event timestamp is ISO8601 UTC. kind is dns-query, dns-answer or tcp. src/dst are documentation IPv4 or 2001:db8::/32 IPv6; sport/dport are transport ports. DNS events contain name, transactionId and records; each record has owner, type(A,AAAA,CNAME), value and ttl(seconds). Questions use QTYPE A; the authored response includes additional AAAA/CNAME answer records deliberately for a mixed-record teaching example, not a claim about typical server behavior. TCP has flags, seq and ack; no application payload. The dual-stack client role is declared synthetic scenario metadata, not inferred identity.

All frames are Ethernet II; classic little-endian PCAP, microsecond timestamps, snaplen65535, full packet bytes, valid calculated checksums. No production collection or sensor coverage is measured. Rebuild is deterministic. The full builder refuses existing outputs. The verifier uses approved fixed capture SHA256, decoded count, DNS pairing and RR semantics, IPv6, viewpoint and checksum/malformed checks; it does not prove incident authenticity or application hostname.

Decoded TSV columns are actual TShark fields; comma-joined multiple RR values preserve answer order. DNS IDs may display hexadecimal. Empty fields indicate no field in that packet. A mixed-address response is one reply; records are not separate replies. Stored stderr includes the observed root warning; learners need not run as root. Linux CLI execution is proven; GUI actions are learner instructions, and Windows commands remain unexecuted.

Full capture hashes are fixed in verify_fixtures.py. limited-practice.pcap SHA256 bfd77ddf38618a3a19edc8ff29898d1d47cb349b2468789efb47e56cf165ae1c is built by limited_builder.py from limited-fixture-plan.json (v1), with 20events, only IPv4 and single-A replies. It is supplemental and cannot replace the full three-file exercise. No existing public dns-baseline capture is changed.

Complete exact plan bytes (including event owners, types, values, timestamps, endpoints, observation metadata and event order) are bound by a fixed SHA256 in verify_fixtures.py, in addition to fixed capture hashes. Any plan edit fails closed, even if captures are unchanged. The selected decoded RR owner/type arrays are also explicitly checked. This does not imply a generic arbitrary-plan validator.

The read-only baseline-preservation-receipt.json identifies the original published and inspected current GitHub revisions, blob hashes, byte-identical SHA256 and actual six-packet decoding of the separate existing dns-baseline capture. No checkout or Git CLI was used; exact remote revision inspection supplies the repository identity. Original executed-proof.json and verify/reject logs record the first verifier version and are historical execution receipts; executed-proof-v2.json and *-v2 logs record the current stricter verifier. Existing output logs are never silently rewritten.
