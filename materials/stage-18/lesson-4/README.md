# Supplemental pivoting and multi-hop practice

This complete offline synthetic lab models two observation points. It is separate from the saved lecture’s unavailable incident; it establishes neither a real intrusion nor the identity of a human operator. No network traffic needs to be sent. Use an authorized isolated practice machine. The supplied native execution evidence uses Ubuntu 24.04 and Wireshark 4.4.0; Windows commands below are learner instructions, not a claim of Windows execution.

Download and extract the whole kit. Keep its flat directory intact. Read [worksheet.md](worksheet.md) before [answer-guide.md](answer-guide.md). Open [ab.pcap](ab.pcap) and [bc.pcap](bc.pcap) separately in Wireshark. Each has its own frame numbering. Supporting records: [capture_inventory.csv](capture_inventory.csv), [address_assignments.csv](address_assignments.csv), [host_events.csv](host_events.csv), [identity_events.csv](identity_events.csv), [work_orders.csv](work_orders.csv), and their source [identity_and_work_orders.json](identity_and_work_orders.json). [DATA_DICTIONARY.md](DATA_DICTIONARY.md) explains their synthetic fields.

Record the modeled sensor, UTC window, excluded link, collection gaps, authored time basis, and unmeasured clock offset from the inventory. Select an absolute UTC date-and-time display. Precision does not improve timestamps. Open Statistics > Conversations, select TCP, record the active display filter and whether Limit to display filter is checked. Inspect packets supporting each row. Try `ip.addr == 192.0.2.20`, then `ip.addr == 192.0.2.10 && ip.addr == 192.0.2.20` in ab and `ip.addr == 192.0.2.20 && ip.addr == 192.0.2.30` in bc. Clear the filter before comparing full-file counts. Flow Graph ordering cannot supply a missing edge or establish causation.

## Rebuild and validate

Python 3.11+ uses only its standard library. From the extracted kit directory, run `python3 build_fixture.py --out scratch-captures`; on Windows use `py -3 build_fixture.py --out scratch-captures`. Existing output files are refused. The builder reads executed-fixture-spec.json, partitions its construction events into two sensor files, and pads each Ethernet frame to at least 60 bytes excluding FCS. It does not capture traffic. Use a fresh destination; never overwrite evidence. Run `python3 validate_fixture.py --root .` (Windows: `py -3 validate_fixture.py --root .`) against the original kit. Compare rebuilt hashes with the independent-validation.json receipt. To validate rebuilt copies, copy the scenario CSV and JSON records into that fresh directory, then select it with --root.

On Linux, run `tshark -r ab.pcap -q -z conv,tcp` and the same command for bc.pcap. On Windows PowerShell, use `& 'C:/Program Files/Wireshark/tshark.exe' -r 'ab.pcap' -q -z conv,tcp` and repeat for bc.pcap. For each file run `tshark -r ab.pcap -Y 'ip.addr == 192.0.2.20' -T fields -e frame.number -e frame.time_epoch -e ip.src -e ip.dst -e tcp.flags`; substitute bc.pcap and your executable path as needed. The supplied actual-cli-execution.json and ab-/bc- stdout/stderr files are actual Linux executions, with exact binary path and exit statuses. These do not establish Windows compatibility checks.
