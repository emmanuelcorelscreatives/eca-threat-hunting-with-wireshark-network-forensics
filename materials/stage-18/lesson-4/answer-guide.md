# Answer guide — verified synthetic worked example

The delivered ab.pcap and bc.pcap each contain 10 independently numbered TCP frames and are 804 bytes on disk. Each carries 620 recorded Ethernet bytes excluding FCS: eight 60-byte frames and two 70-byte data frames. Native TShark TCP Conversations reports 370 bytes from initiator to responder and 250 bytes in reverse, 620 total. PCAP disk bytes include its 24-byte global header and ten 16-byte record headers. These are distinct units.

A `192.0.2.10:51022` initiates toward B `192.0.2.20:2222` at 2026-01-15 10:00:00 UTC in ab. B `192.0.2.20:52022` initiates toward C `192.0.2.30:2222` at 10:02:01 UTC in bc. Both exchanges last 5.2 seconds. In each file frames 1–3 form SYN/SYN-ACK/ACK, frames 4 and 6 carry opposite-direction 16-byte fictional markers, and frames 8–10 close the connection. The initiator sends six packets; the responder sends four. Thus `ab:1–10` supports bidirectional A–B TCP and `bc:1–10` supports bidirectional B–C TCP; the 121-second start difference does not prove a causal chain. TCP/2222 and opaque markers are not decoded remote-service, authentication, command, or authorization evidence.
